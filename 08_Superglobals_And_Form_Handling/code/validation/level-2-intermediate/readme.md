# Контактная форма на PHP (средний уровень)

Этот пример показывает хороший "промежуточный" подход:

- логика вынесена из HTML в отдельные файлы;
- валидация оформлена отдельным классом;
- форма умеет показывать ошибки и сохранять введённые значения.

Подходит для студентов, которые уже прошли базовый PHP и хотят писать более чистый код.

## Что находится в папке

- `index.php`- отображение формы и ошибок.
- `handler.php`- обработка POST-запроса.
- `validator.php`- класс `Validator` с правилами проверки.

## Как работает пример

1. Пользователь открывает `index.php`.
2. В начале `index.php` подключается `handler.php`.
3. `handler.php` проверяет метод запроса:
   - если `GET`, просто создаёт пустые `$errors` и `$oldValues`;
   - если `POST`, забирает данные, проверяет их и либо сохраняет, либо возвращает ошибки.
4. `index.php` выводит форму:
   - старые значения через функцию `old()`;
   - первую ошибку поля через функцию `error()`.

## Роль каждого файла

## `index.php`

Отвечает только за интерфейс и вывод:

- подключает `handler.php`;
- содержит 2 маленьких хелпера:
  - `old($field, $oldValues)`- возвращает старое значение поля в безопасном виде (`htmlspecialchars`);
  - `error($field, $errors)`- возвращает первую ошибку поля;
- выводит сообщение об успехе по `?success=1`;
- подсвечивает поля с ошибкой классом `has-error`.

Идея: HTML остаётся читаемым, а тяжёлая логика валидации не смешивается с разметкой.

## `handler.php`

Центр обработки формы:

1. Подключает `Validator`.
2. Инициализирует:
   - `$errors = [];`
   - `$oldValues = [];`
3. Если запрос `POST`:
   - собирает и очищает входные данные (`trim`);
   - задаёт правила валидации;
   - запускает `$validator->validate()`.
4. Если валидация прошла:
   - записывает данные в `submissions.txt`;
   - делает редирект на `index.php?success=1`.
5. Если есть ошибки:
   - заполняет `$errors`;
   - сохраняет `$oldValues`, чтобы пользователь не вводил всё заново.

Этот сценарий реализует правильный паттерн PRG: `POST -> Redirect -> GET`.

## `validator.php` и класс `Validator`

Это универсальный класс проверки данных.

### Что хранит

- `$data`- входные данные формы.
- `$rules`- правила для каждого поля.
- `$errors`- найденные ошибки.

### Основные методы

- `validate(): bool`- запускает проверку всех полей.
- `getErrors(): array`- возвращает все ошибки.
- `getError(string $field): string`- первая ошибка поля.
- `hasErrors(): bool`- есть ли ошибки вообще.

### Поддерживаемые правила

- `required`- обязательное поле.
- `email`- корректный email.
- `min:N`- минимальная длина.
- `max:N`- максимальная длина.
- `enum:a,b,c`- значение только из списка.
- `numeric`- должно быть числом.
- `alpha`- только буквы (включая кириллицу).
- `url`- корректный URL.

### Как работает проверка

Для каждого поля класс проходит по всем правилам и вызывает `checkRule(...)`.

- Правила с параметрами (`min:5`, `enum:1,2,3`) разделяются на имя и параметр.
- Если значение пустое и правило не `required`, правило пропускается.
- При ошибке сообщение добавляется в `$errors[$field][]`.

## Пример правил в этом проекте

- `name`: `required`, `min:3`, `max:50`
- `email`: `required`, `email`
- `message`: `required`, `min:10`, `max:1000`
- `category`: `required`, `enum:1,2,3`
