## Вопросы для самопроверки

1. Почему обращение к свойству записывается как `$product->name`, а не `$product->$name`, и что произойдёт при опечатке в имени свойства?
2. Почему блок `catch (Exception $e)` не перехватывает `TypeError`?
3. Чем запись `public private(set) int $stock` отличается от `public readonly int $stock` и от пары "закрытое свойство и геттер"?
4. Почему после присваивания `$b = $a` изменение `$b->price` изменяет и `$a->price`, а для массивов этого не происходит?
5. Что получает класс, объявленный как `class Admin extends User {}`, и почему его объект можно передать в функцию с параметром типа `User`?
6. Что произойдёт, если конструктор класса `Admin` не вызовет `parent::__construct()`?
7. Какие недостатки функции `sendNotification()` с ветвлением по названию канала устраняет полиморфизм?
8. Почему абстрактный класс `Notifier` надёжнее, чем несколько классов с одинаковым методом `send()` без общего типа?
9. Почему в веб-разработке общий тип для разных реализаций чаще задают интерфейсом, чем родительским классом?

## Ретроспектива

В главе 4 товар MiniShop был описан ассоциативным массивом, а в главе 5 действия над товарами были оформлены функциями. У такого описания есть ограничение: массив не гарантирует ни набора ключей, ни соблюдения правил. Остаток на складе можно уменьшить функцией с проверкой, но любая строка программы может записать `$product['stock'] = -5` в обход этой функции, а опечатка в ключе `'prise'` обнаружится только предупреждением при чтении.

Объектно-ориентированное программирование решает эту проблему, объединяя данные и правила их изменения в классе. Понятия класса, объекта, инкапсуляции, наследования и полиморфизма знакомы вам по курсам программирования, поэтому глава не повторяет их общее объяснение. Она показывает, как эти понятия выражены в PHP: синтаксис, поведение объектов и средства языка, которых нет или которые устроены иначе в других языках.

Тема разделена на две главы. Эта глава рассматривает устройство класса, исключения, видимость, наследование, абстрактные классы, полиморфизм и интерфейсы. Статические свойства и методы, а также другие средства организации классов рассматриваются во второй части.

## Классы и объекты в PHP

### Объявление класса и создание объекта

**Класс (class)** - описание структуры и поведения объектов определённого вида. **Объект (object)**, или **экземпляр класса (instance)**, - значение, созданное на основе класса и хранящее собственные данные[^1].

_Синтаксис_

```php
class ClassName
{
    // свойства и методы
}

$object = new ClassName();

$object->propertyName
$object->methodName(arguments)
```

- Имя класса по стандарту PSR-1 записывается в стиле `StudlyCaps`: каждое слово с заглавной буквы, без разделителей, например `Product` или `ShoppingCart`[^2].
- По стандарту PSR-12 открывающая фигурная скобка класса располагается на отдельной строке[^3].
- Оператор `new` создаёт новый объект указанного класса. Каждый вызов `new` создаёт отдельный объект.
- Оператор `->` обращается к свойству или методу объекта.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public string $name = '';
    public int $price = 0;
}

$laptop = new Product();
$laptop->name = 'Ноутбук Lenovo IdeaPad 3';
$laptop->price = 14999;

$mouse = new Product();
$mouse->name = 'Мышь Logitech M185';
$mouse->price = 299;

echo $laptop->name . '<br>';   // Ноутбук Lenovo IdeaPad 3
echo $mouse->price;            // 299
```

Обратите внимание на запись обращения к свойству: знак `$` ставится перед именем переменной, но не перед именем свойства. Запись `$laptop->$name` синтаксически допустима, но означает другое: имя свойства берётся из переменной `$name`.

Функция `var_dump()` из главы 3 выводит объект вместе с именем класса:

```php
var_dump($laptop);
```

```text
object(Product)#1 (2) {
  ["name"]=>
  string(31) "Ноутбук Lenovo IdeaPad 3"
  ["price"]=>
  int(14999)
}
```

- Запись `object(Product)` означает объект класса `Product`.
- Число после знака `#` является идентификатором объекта внутри текущего скрипта.
- Число в скобках показывает количество свойств.

### Свойства

**Свойство (property)** - переменная, объявленная внутри класса, каждый объект хранит собственное значение каждого свойства[^4].

_Синтаксис_

```php
modifier type $propertyName;
modifier type $propertyName = defaultValue;
```

- `modifier` - модификатор видимости. До раздела "Видимость и инкапсуляция" в примерах используется `public`.
- `type` - объявление типа, рассмотренное в главе 5. Тип проверяется при каждом присваивании: при `declare(strict_types=1)` запись строки в свойство типа `int` завершается ошибкой `TypeError`.
- `defaultValue` - значение, известное до выполнения программы: литерал, константа, массив или выражение из них. Вызов функции здесь недопустим.

В PHP есть две особенности свойств, которые отличают его от многих других языков:

1. Типизированное свойство без значения по умолчанию после создания объекта находится в неинициализированном состоянии. Это не `null` и не пустая строка: у свойства нет значения вообще, и попытка его прочитать завершается ошибкой[^4]:

   ```php
   <?php

   declare(strict_types=1);

   class Product
   {
       public string $name;
       public int $price = 0;
   }

   $product = new Product();
   echo $product->name;
   // Fatal error: Uncaught Error: Typed property Product::$name must not be accessed before initialization
   ```

2. Если присвоить значение свойству, которое не объявлено в классе, PHP создаёт так называемое **динамическое свойство**. Начиная с PHP 8.2 это сопровождается уведомлением `Deprecated`, которое означает, что поведение будет запрещено в одной из следующих версий языка[^4]:

   ```php
   $product->prise = 100;
   // Deprecated: Creation of dynamic property Product::$prise is deprecated
   ```

В отличие от массива, где опечатка в ключе при записи не вызывала никакого сообщения, класс с перечисленными свойствами позволяет обнаружить её сразу.

### Методы и ключевое слово `$this`

**Метод (method)** - функция, объявленная внутри класса[^1].

_Синтаксис_

```php
modifier function methodName(type $parameter, ...): returnType
{
    // тело метода
}
```

- Имена методов по стандарту PSR-1 записываются в стиле `camelCase`[^2].
- Внутри метода доступна переменная `$this`.

**$this** - переменная, которая внутри метода обозначает объект, для которого метод был вызван[^1].

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public string $name = '';
    public int $price = 0;

    public function priceWithDiscount(int $percent): float
    {
        return $this->price - $this->price * $percent / 100;
    }
}

$laptop = new Product();
$laptop->price = 14999;

$mouse = new Product();
$mouse->price = 299;

echo $laptop->priceWithDiscount(15) . '<br>';   // 12749.15
echo $mouse->priceWithDiscount(15);             // 254.15
```

При вызове `$laptop->priceWithDiscount(15)` переменная `$this` обозначает объект `$laptop`, при вызове `$mouse->priceWithDiscount(15)` - объект `$mouse`.

> [!IMPORTANT]
>
> В отличие от Java и C++, в PHP к свойствам объекта внутри метода обращаются только через `$this`. Запись `$price` внутри метода означает локальную переменную метода, а не свойство, и по правилам области видимости из главы 5 такая переменная не определена.

### Конструктор

**Конструктор (constructor)** - метод с именем `__construct`, который PHP автоматически вызывает для каждого нового объекта сразу после его создания[^5].

_Синтаксис_

```php
public function __construct(type $parameter, ...)
{
    // инициализация свойств
}
```

- Имя начинается с двух символов подчёркивания.
- Аргументы конструктора передаются в выражении `new ClassName(arguments)`.
- Тип результата для конструктора не указывается.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public string $name;
    public int $price;

    public function __construct(string $name, int $price)
    {
        $this->name = $name;
        $this->price = $price;
    }
}

$laptop = new Product('Ноутбук Lenovo IdeaPad 3', 14999);

echo $laptop->name;   // Ноутбук Lenovo IdeaPad 3
```

В этом конструкторе каждое свойство упоминается трижды:

- в объявлении свойства,
- в параметре,
- в присваивании `$this->name = $name`.

Начиная с PHP 8.0 эту запись можно сократить[^5].

**Продвижение параметров конструктора (constructor property promotion)** - сокращённая запись, при которой параметр конструктора с модификатором видимости одновременно объявляет свойство и присваивает ему значение аргумента.

_Синтаксис_

```php
public function __construct(
    modifier type $property1,
    modifier type $property2 = defaultValue,
) {
    // дополнительные действия
}
```

- Параметр с модификатором видимости становится свойством с тем же именем и типом.
- Тело конструктора может быть пустым, но фигурные скобки обязательны.
- Продвинутые и обычные параметры можно сочетать в одном конструкторе.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        public int $price,
        public int $stock = 0,
    ) {
    }
}

$laptop = new Product('Ноутбук Lenovo IdeaPad 3', 14999, 3);
$cable = new Product('Кабель HDMI', 149);

echo $cable->stock;   // 0
```

Свойства `name` и `price` объявлены и инициализированы так же, как в предыдущем примере, но без повторений; добавлено свойство `stock` со значением по умолчанию.

Конструктор можно вызывать с _именованными аргументами_: `new Product(name: 'Кабель HDMI', price: 149)`.

> [!NOTE]
>
> В PHP у класса может быть только один конструктор. Перегрузки методов, то есть нескольких методов с одним именем и разными параметрами, как в Java или C++, в PHP нет. Её роль выполняют параметры со значениями по умолчанию и именованные аргументы.

## Исключения в PHP

Конструктор гарантирует, что свойства заполнены, но не гарантирует, что значения осмысленны: вызов `new Product('Ноутбук', -100)` создаст товар с отрицательной ценой. Конструктор не возвращает значения, поэтому сообщить о неверных данных значением `false`, как это делает встроенная функция `array_search()` из главы 4, он не может. Для этого используются исключения.

**Исключение (exception)** - объект, описывающий ошибочную ситуацию, который выбрасывается оператором `throw` или самим PHP и передаётся вверх по цепочке вызовов до ближайшего подходящего обработчика[^6].

Механизм `try`/`catch` устроен в PHP так же, как в других языках, поэтому ниже приведён только его синтаксис.

_Синтаксис_

```php
throw new ExceptionClass('message');

try {
    // код, который может выбросить исключение
} catch (ExceptionClass $e) {
    // обработка
} catch (ExceptionClass1 | ExceptionClass2 $e) {
    // обработка исключения любого из перечисленных классов
} finally {
    // выполняется всегда
}
```

- `ExceptionClass` - класс исключения. Для недопустимого значения аргумента предназначен встроенный класс `InvalidArgumentException`[^7].
- Метод `$e->getMessage()` возвращает текст сообщения, переданный при создании исключения.
- Блок `catch` срабатывает для исключения указанного класса и его наследников (раздел "Наследование"). Если подходят несколько блоков, срабатывает первый по порядку[^6].
- Классы в одном блоке `catch` можно перечислить через `|`.
- Блок `finally` выполняется после `try` и `catch` независимо от того, было ли выброшено исключение. Блок `try` должен сопровождаться хотя бы одним блоком `catch` или `finally`.
- Исключение, которое не перехватил ни один блок, завершает скрипт с фатальной ошибкой `Uncaught`.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        public int $price,
    ) {
        if ($price < 0) {
            throw new InvalidArgumentException('Цена не может быть отрицательной');
        }
    }
}

try {
    $product = new Product('Ноутбук', -100);
    echo 'Товар создан';
} catch (InvalidArgumentException $e) {
    echo 'Ошибка: ' . $e->getMessage();
}

echo '<br>Скрипт продолжает работу';
// Ошибка: Цена не может быть отрицательной<br>Скрипт продолжает работу
```

Объект с отрицательной ценой создан не был: выполнение конструктора прервалось на `throw`, строка `echo 'Товар создан'` была пропущена, и управление перешло в блок `catch`.

В PHP ошибки `TypeError` и `DivisionByZeroError` тоже являются объектами-исключениями, но выбрасывает их сам PHP, и относятся они к отдельной ветви иерархии встроенных исключений[^8].

```text
Throwable
├── Exception
│   ├── LogicException
│   │   └── InvalidArgumentException
│   └── RuntimeException
└── Error
    ├── TypeError
    │   └── ArgumentCountError
    └── ArithmeticError
        └── DivisionByZeroError
```

_Схема 6.1. Фрагмент иерархии встроенных исключений PHP_

На схеме 6.1 под `Throwable` расположены две ветви.

- Ветвь `Exception` содержит исключения, которые, как правило, выбрасывает код программы или подключаемые библиотеки: `LogicException` объединяет ошибки в логике вызова, например недопустимый аргумент, а `RuntimeException` - ошибки, которые обнаруживаются только во время выполнения.
- Ветвь `Error` содержит ошибки, которые выбрасывает сам PHP: неверный тип, нехватка аргументов, деление на ноль, обращение к неинициализированному свойству[^8].

Поскольку `Error` не входит в ветвь `Exception`, блок `catch (Exception $e)` не перехватывает `TypeError` и другие ошибки PHP. Перехватить исключения обеих ветвей позволяет `catch (Throwable $e)`.

> [!WARNING]
>
> Не перехватывайте исключения только ради того, чтобы они исчезли. Пустой блок `catch` скрывает ошибку так же, как оператор `@`: программа продолжает работу с неверными данными, а причина сбоя остаётся неизвестной. Перехватывать исключение следует там, где известно, что с ним делать.

## Видимость и инкапсуляция

### Модификаторы видимости

Исключение в конструкторе не позволяет создать товар с отрицательной ценой. Однако если свойство `price` открыто, любой код может изменить его после создания: `$product->price = -100;`. Проверку в конструкторе в этом случае можно обойти одной строкой.

**Член класса (class member)** - свойство, метод или константа (раздел "Константы класса"), объявленные в классе.

**Модификатор видимости (visibility modifier)** - ключевое слово перед объявлением члена класса, определяющее, из какого кода к нему можно обращаться[^9].

| Модификатор | Название   | Где доступен член класса                                                         |
| ----------- | ---------- | -------------------------------------------------------------------------------- |
| `public`    | Открытый   | В любом месте программы                                                          |
| `protected` | Защищённый | Внутри класса и в классах, связанных с ним наследованием (раздел "Наследование") |
| `private`   | Закрытый   | Только внутри методов того класса, в котором он объявлен                         |

Метод или константа без модификатора считаются `public`[^9]; у свойства модификатор обязателен. Стандарт PSR-12 требует явно указывать видимость и у методов[^3]. Обращение к закрытому члену извне завершается ошибкой `Error`:

```php
echo $product->price;
// Fatal error: Uncaught Error: Cannot access private property Product::$price
```

### Понятие инкапсуляции

**Инкапсуляция (encapsulation)** - один из принципов объектно-ориентированного программирования, согласно которому объект скрывает своё внутреннее состояние и позволяет изменять его только через собственные методы, обеспечивающие соблюдение правил. Для получения значения закрытого свойства обычно создают открытый метод-геттер.

**Геттер (getter)** - открытый метод, возвращающий значение закрытого свойства. Имя геттера по соглашению начинается с `get`: `getPrice()`, `getStock()`.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        private int $price,
        private int $stock = 0,
    ) {
        if ($price < 0 || $stock < 0) {
            throw new InvalidArgumentException('Цена и остаток не могут быть отрицательными');
        }
    }

    public function getPrice(): int
    {
        return $this->price;
    }

    public function getStock(): int
    {
        return $this->stock;
    }

    public function decreaseStock(int $quantity): void
    {
        if ($quantity <= 0 || $quantity > $this->stock) {
            throw new InvalidArgumentException('Недопустимое количество');
        }

        $this->stock -= $quantity;
    }
}

$laptop = new Product('Ноутбук', 14999, 3);
$laptop->decreaseStock(2);

echo $laptop->getStock();   // 1
```

Остаток невозможно сделать отрицательным: прямое присваивание запрещено модификатором `private`, а единственный способ изменения, метод `decreaseStock()`, проверяет каждый вызов. Для цены метода изменения нет вовсе, поэтому после создания объекта её можно только прочитать.

Инкапсуляция не означает, что каждому закрытому свойству нужна пара методов `get` и `set`. Метод `setStock(int $stock)`, присваивающий любое значение без проверки, вернул бы ту же проблему, что и открытое свойство. Методы проектируются как действия предметной области: "_уменьшить остаток_", "_применить скидку_", а не "_присвоить поле_". Поэтому закрытые свойства не обязательно должны иметь геттеры и сеттеры, если это не требуется логикой предметной области.

### Асимметричная видимость

В классе выше геттеры `getPrice()` и `getStock()` не содержат никакой логики: они существуют только потому, что модификатор `private` запрещает не только запись, но и чтение. Защитить нужно было только запись. Начиная с PHP 8.4 видимость чтения и записи свойства можно задать раздельно[^9].

**Асимметричная видимость (asymmetric visibility)** - объявление свойства с разными модификаторами видимости для чтения и для записи.

_Синтаксис_

```php
public private(set) type $property;
public protected(set) type $property;
private(set) type $property;
```

- Первый модификатор задаёт видимость чтения, модификатор с `(set)` задаёт видимость записи.
- Видимость записи должна быть такой же или более строгой, чем видимость чтения. Запись `protected public(set)` завершается фатальной ошибкой при объявлении класса.
- Асимметричная видимость применяется только к типизированным свойствам.
- Если видимость чтения равна `public`, её можно опустить: `private(set)` означает то же, что `public private(set)`.
- Модификаторы допускаются и в продвинутом параметре конструктора.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        public private(set) int $price,
        public private(set) int $stock = 0,
    ) {
        if ($price < 0 || $stock < 0) {
            throw new InvalidArgumentException('Цена и остаток не могут быть отрицательными');
        }
    }

    public function decreaseStock(int $quantity): void
    {
        if ($quantity <= 0 || $quantity > $this->stock) {
            throw new InvalidArgumentException('Недопустимое количество');
        }

        $this->stock -= $quantity;
    }
}

$laptop = new Product('Ноутбук', 14999, 3);
$laptop->decreaseStock(2);

echo $laptop->stock;   // 1
$laptop->stock = 100;
// Fatal error: Uncaught Error: Cannot modify private(set) property Product::$stock from global scope
```

Класс стал короче на два метода и сохранил прежнюю гарантию: читать остаток может любой код, изменить его можно только методом `decreaseStock()`. Запись `from global scope` в сообщении означает, что попытка изменения сделана вне методов класса.

Асимметричная видимость не отменяет геттеры полностью. Метод по-прежнему нужен, если значение вычисляется (`priceWithDiscount()`) или если при чтении требуется дополнительная логика.

### Неизменяемые свойства

Некоторые данные товара не должны меняться после создания объекта вовсе, например код товара (`id`) и название. Для них в PHP 8.1 появился отдельный модификатор[^4].

**Неизменяемое свойство (readonly property)** - свойство, значение которого можно присвоить только один раз; любая последующая попытка изменения завершается ошибкой.

_Синтаксис_

```php
modifier readonly type $propertyName;
```

- Модификатор `readonly` применяется только к типизированным свойствам, значение по умолчанию для него указывать нельзя.
- Значение присваивается один раз, обычно в конструкторе. Модификатор допускается в продвинутом параметре конструктора.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $name,
    ) {
    }
}

$product = new Product(1, 'Ноутбук');

echo $product->name;           // Ноутбук
$product->name = 'Планшет';
// Fatal error: Uncaught Error: Cannot modify readonly property Product::$name
```

Асимметричная видимость и `readonly` решают разные задачи.

| Свойство                    | `public private(set)`  | `public readonly`                |
| --------------------------- | ---------------------- | -------------------------------- |
| Кто может читать            | Любой код              | Любой код                        |
| Кто может изменять          | Методы класса          | Никто после первого присваивания |
| Сколько раз можно присвоить | Сколько угодно         | Один раз                         |
| Пример в MiniShop           | Остаток, статус заказа | Код товара, название             |

## Константы класса

Свойства принадлежат объекту: у каждого объекта своё значение. Некоторые значения относятся ко всему классу, например код валюты магазина. Для них используются константы класса[^10].

**Константа класса (class constant)** - именованное неизменяемое значение, объявленное внутри класса и общее для всех его объектов.

Константа принадлежит классу, а не объекту, поэтому к ней обращаются через имя класса и оператор `::`.

**Оператор разрешения области видимости `::` (scope resolution operator)** - оператор обращения к членам, которые принадлежат классу, а не отдельному объекту, например к константам[^11].

_Синтаксис_

```php
modifier const CONSTANT_NAME = value;

ClassName::CONSTANT_NAME
self::CONSTANT_NAME
```

- Имена констант по стандарту PSR-1 записываются заглавными буквами с подчёркиваниями[^2].
- Вне класса используется имя класса, внутри методов класса - ключевое слово `self`, обозначающее текущий класс.
- После `::` знак `$` перед именем константы не ставится.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public const CURRENCY = 'лей';
    public const MAX_DISCOUNT = 50;

    public function __construct(
        public readonly string $name,
        public private(set) int $price,
    ) {
    }

    public function priceWithDiscount(int $percent): float
    {
        if ($percent < 0 || $percent > self::MAX_DISCOUNT) {
            throw new InvalidArgumentException('Недопустимый размер скидки');
        }

        return $this->price - $this->price * $percent / 100;
    }
}

$laptop = new Product('Ноутбук', 14999);

echo $laptop->priceWithDiscount(15) . ' ' . Product::CURRENCY;   // 12749.15 лей
```

Оператор `::` встретится в этой главе ещё раз, в разделе "Наследование", для обращения к членам родительского класса.

## Объект как значение

### Массив копируется, объект нет

В главах 4 и 5 было установлено, что массив при присваивании и при передаче в функцию копируется[^12]. Объекты ведут себя иначе, и это различие является одним из главных источников ошибок при переходе от массивов к объектам.

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        public int $price,
    ) {
    }
}

$arrayA = ['name' => 'Ноутбук', 'price' => 14999];
$arrayB = $arrayA;
$arrayB['price'] = 9999;
echo $arrayA['price'] . '<br>';   // 14999, массив $arrayA не изменился

$objectA = new Product('Ноутбук', 14999);
$objectB = $objectA;
$objectB->price = 9999;
echo $objectA->price;    // 9999, изменился и $objectA
```

Переменная с массивом хранит сам массив, поэтому присваивание создаёт вторую копию. Переменная с объектом хранит не сам объект, а его идентификатор[^13].

**Идентификатор объекта (object identifier)** - значение, по которому PHP находит объект; переменная, содержащая объект, на самом деле содержит его идентификатор.

При присваивании `$objectB = $objectA` копируется идентификатор, и обе переменные указывают на один и тот же объект. Номер `#1` в выводе `var_dump()` из раздела "Объявление класса и создание объекта" и есть такой идентификатор.

### Копирование и сравнение объектов

Если нужна независимая копия объекта, используется оператор `clone`[^14].

_Синтаксис_

```php
$copy = clone $object;
```

- Создаёт новый объект того же класса и копирует в него значения всех свойств.
- Копирование поверхностное: если свойство содержит другой объект, копируется идентификатор, и оригинал с копией будут ссылаться на один вложенный объект.

Операторы сравнения из главы 3 применимы и к объектам, но их смысл для объектов определяется отдельно[^15].

| Выражение   | Результат `true`, если                                                                    |
| ----------- | ----------------------------------------------------------------------------------------- |
| `$a == $b`  | Объекты одного класса и значения всех свойств попарно равны при сравнении оператором `==` |
| `$a === $b` | Обе переменные указывают на один и тот же объект                                          |

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public string $name,
        public int $price,
    ) {
    }
}

$a = new Product('Мышь', 299);
$b = clone $a;
$c = $a;

var_dump($a == $b);    // bool(true), данные одинаковы
var_dump($a === $b);   // bool(false), это разные объекты
var_dump($a === $c);   // bool(true), это один объект

$b->price = 249;
echo $a->price;        // 299, копия независима
```

Выбор оператора сравнения зависит от вопроса: "одинаковы ли данные" или "тот ли это самый объект".

<details>
<summary>Проверьте себя. Что выведет следующий код?</summary>

```php
$a = new Product('Ноутбук', 14999);
$b = $a;
$b = new Product('Мышь', 299);
$b->price = 100;

echo $a->price;
```

Будет выведено `14999`. После строки `$b = $a` обе переменные указывали на один объект, но следующая строка присвоила `$b` идентификатор нового объекта. Изменение цены затронуло только новый объект.

</details>

## Класс как тип

В главе 5 в объявлениях типов использовались `int`, `string`, `array` и другие встроенные типы. Имя класса также является типом: параметр с типом `Product` принимает только объекты класса `Product`[^16].

_Синтаксис_

```php
function functionName(ClassName $parameter): ClassName
function functionName(?ClassName $parameter): ?ClassName
```

- Тип `ClassName` требует объект указанного класса. Передача значения другого типа завершается ошибкой `TypeError`.
- Тип `?ClassName` дополнительно допускает `null`, как и `?int` в главе 5.

Типичный случай использования `?ClassName` - функция поиска, которая возвращает найденный объект или `null`.

_Пример_

```php
<?php

declare(strict_types=1);

class Product
{
    public function __construct(
        public readonly int $id,
        public readonly string $name,
    ) {
    }

    public function url(): string
    {
        return '/product.php?id=' . $this->id;
    }
}

function findProduct(array $products, int $id): ?Product
{
    foreach ($products as $product) {
        if ($product->id === $id) {
            return $product;
        }
    }

    return null;
}

$catalog = [
    new Product(1, 'Ноутбук'),
    new Product(2, 'Мышь'),
];

$found = findProduct($catalog, 3);

var_dump($found);   // NULL
```

Товара с кодом 3 в каталоге нет, поэтому функция вернула `null`. Вызов метода у `null` завершается ошибкой:

```php
echo $found->url();
// Fatal error: Uncaught Error: Call to a member function url() on null
```

Чтобы не проверять результат поиска на `null` перед каждым обращением, в PHP 8.0 появился отдельный оператор[^1].

**Оператор `?->` (nullsafe operator)** - оператор обращения к свойству или методу, который возвращает `null`, если значение слева равно `null`, вместо ошибки.

_Синтаксис_

```php
$object?->property
$object?->method(arguments)
```

- Если `$object` равен `null`, выражение возвращает `null`, а метод не вызывается и его аргументы не вычисляются.
- Если `$object` не равен `null`, выражение работает так же, как обычное обращение через `->`.

_Пример_

```php
var_dump($found?->url());                     // NULL, метод не вызывался
var_dump(findProduct($catalog, 1)?->url());   // string(17) "/product.php?id=1"

echo $found?->url() ?? '/catalog.php';        // /catalog.php
```

В последней строке оператор `??` из главы 3 подставляет значение по умолчанию, если оператор `?->` вернул `null`: ссылка ведёт на страницу товара, а если товар не найден, на каталог.

Проверить, является ли значение объектом определённого класса, позволяет оператор `instanceof`[^17].

_Синтаксис_

```php
$value instanceof ClassName
```

- Возвращает `true`, если значение является объектом указанного класса или его наследника (раздел "Наследование").
- Если значение не является объектом, возвращает `false` без ошибки.

_Пример_

```php
var_dump($catalog[0] instanceof Product);   // bool(true)
var_dump($found instanceof Product);        // bool(false), $found равно null
```

В собственном коде объявление типа параметра обычно избавляет от необходимости проверять `instanceof` вручную: PHP выполнит проверку при вызове.

## Наследование

### Ключевое слово extends

**Наследование (inheritance)** - механизм, при котором класс получает свойства, методы и константы другого класса и может добавлять собственные или изменять унаследованные[^18].

**Родительский класс (parent class)** - класс, на основе которого создан другой класс. **Дочерний класс (child class)**, или наследник, - класс, созданный на основе родительского.

_Синтаксис_

```php
class ChildClass extends ParentClass
{
    // новые и изменённые члены класса
}
```

- Дочерний класс получает открытые и защищённые (`public` и `protected`) свойства, методы и константы родителя. Закрытые (`private`) члены родителя дочернему классу недоступны[^18].
- Класс может наследовать только одному классу. Запись `extends A, B` является синтаксической ошибкой. Наследник, в свою очередь, может иметь собственных наследников[^1].

_Пример_

Рассмотрим пример. В приложении есть пользователи, среди которых есть обычные покупатели и администраторы.

```php
<?php

declare(strict_types=1);

class User
{
    public function __construct(
        public readonly string $name,
        public readonly string $email,
    ) {
    }

    public function describe(): string
    {
        return $this->name . ' <' . $this->email . '>';
    }

    public function canManage(string $section): bool
    {
        return false;
    }
}

class Admin extends User
{
}

$admin = new Admin('Администратор', 'admin@example.com');

echo $admin->describe() . '<br>';           // Администратор <admin@example.com>
var_dump($admin->canManage('products'));   // bool(false)
```

Тело класса `Admin` пустое, но объект уже имеет свойства `name` и `email`, конструктор и оба метода класса `User`: всё это унаследовано. Пока администратор ничем не отличается от покупателя. Отличия добавляются в следующих разделах.

### Подстановка наследника

Объект дочернего класса является одновременно объектом родительского класса. Всё, что можно сделать с объектом `User`, можно сделать и с объектом `Admin`, поэтому наследник принимается везде, где ожидается родитель:

- Параметр функции с типом `User` примет объект `Admin`.
- Выражение `$admin instanceof User` вернёт `true`.

```php
function greeting(User $user): string
{
    return 'Здравствуйте, ' . $user->name . '!';
}

echo greeting($admin);   // Здравствуйте, Администратор!
```

Функция `greeting()` написана для покупателей, но работает и с администратором без изменений.

То же правило объясняет поведение блоков `catch` из раздела "Исключения в PHP". На схеме 6.1 класс `InvalidArgumentException` является наследником `LogicException`, а тот - наследником `Exception`. Поэтому `catch (Exception $e)` перехватывает и `InvalidArgumentException`. Отсюда правило порядка блоков: более конкретный класс указывается раньше более общего. Блок `catch (InvalidArgumentException $e)`, расположенный после `catch (Exception $e)`, никогда не сработает, потому что исключение перехватит первый подходящий блок[^6]. В отличие от Java, где такой недостижимый блок является ошибкой компиляции, PHP принимает его без сообщений.

### Переопределение методов

Администратор должен отличаться от покупателя поведением: метод `canManage()` для него возвращает `true`, а в списке учётных записей рядом с его именем выводится пометка. Для этого дочерний класс объявляет методы с теми же именами.

**Переопределение метода (method overriding)** - объявление в дочернем классе метода с тем же именем, что и у унаследованного; для объектов дочернего класса вызывается новая реализация[^18].

Часто новая реализация не заменяет родительскую полностью, а дополняет её. Для вызова реализации родителя используется ключевое слово `parent` и оператор `::` из раздела "Константы класса".

_Синтаксис_

```php
parent::methodName(arguments);
parent::__construct(arguments);
```

- `parent` обозначает родительский класс текущего класса.
- Вызов `parent::methodName()` выполняет реализацию метода из родительского класса для текущего объекта `$this`.
- Вызов `parent::__construct()` рассматривается в следующем разделе.

_Пример_

```php
class Admin extends User
{
    public function describe(): string
    {
        return parent::describe() . ' [администратор]';
    }

    public function canManage(string $section): bool
    {
        return true;
    }
}

$admin = new Admin('Администратор', 'admin@example.com');
$customer = new User('Покупатель', 'client@example.com');

echo $admin->describe() . '<br>';      // Администратор <admin@example.com> [администратор]
echo $customer->describe();            // Покупатель <client@example.com>
```

Метод `describe()` в классе `Admin` не повторяет формат строки, а берёт результат родительского метода и добавляет пометку. Если формат в классе `User` изменится, администраторы получат его автоматически.

Переопределённый метод должен быть совместим с методом родителя: код, который работает с объектом `User`, должен без изменений работать и с объектом `Admin`.

**Принцип подстановки Лисков (Liskov Substitution Principle, LSP)** - требование, согласно которому объект наследника должен быть пригоден везде, где ожидается объект родителя.

PHP проверяет формальную часть этого принципа, сигнатуру метода[^1]:

- Нельзя добавить обязательный параметр или сделать необязательный параметр обязательным. Добавлять можно только необязательные параметры.
- Типы параметров и результата должны быть совместимы с объявленными в родителе. Проще всего сохранять их без изменений.
- Доступ можно расширить, но не сузить: метод `protected` можно переопределить как `public`, но не наоборот.

Нарушение сигнатуры обнаруживается при объявлении класса:

```php
class Admin extends User
{
    public function canManage(string $section, int $level): bool
    {
        return $level > 0;
    }
}
// Fatal error: Declaration of Admin::canManage(string $section, int $level): bool
// must be compatible with User::canManage(string $section): bool
```

Любой код, вызывающий `$user->canManage('orders')` с одним аргументом, не смог бы работать с таким наследником, поэтому PHP его не допускает.

### Конструктор наследника и parent::

Администратор с полным доступом встречается редко. Обычно сотруднику открывают только нужные разделы: менеджеру заказы, контент-менеджеру товары. Список разделов передаётся в конструктор `Admin`, поэтому дочерний класс объявляет собственный конструктор.

```php
class Admin extends User
{
    public function __construct(
        string $name,
        string $email,
        private array $sections,
    ) {
    }

    public function canManage(string $section): bool
    {
        return in_array($section, $this->sections, true);
    }
}

$manager = new Admin('Менеджер', 'manager@example.com', ['orders']);

var_dump($manager->canManage('orders'));   // bool(true)
echo $manager->name;
// Fatal error: Uncaught Error: Typed property User::$name must not be accessed before initialization
```

Список разделов сохранён, но имя и адрес остались неинициализированными. Причина в правиле, которое отличает PHP от C++ и Java: если дочерний класс объявляет собственный конструктор, конструктор родителя автоматически не вызывается[^5]. Конструктор `User`, который заполняет `name` и `email`, в этом примере не выполнялся вовсе.

Конструктор родителя вызывается явно:

```php
class Admin extends User
{
    public function __construct(
        string $name,
        string $email,
        private array $sections,
    ) {
        parent::__construct($name, $email);
    }

    // ...
}

$manager = new Admin('Менеджер', 'manager@example.com', ['orders']);

echo $manager->name . '<br>';                // Менеджер
var_dump($manager->canManage('products'));   // bool(false)
```

Параметры `$name` и `$email` в конструкторе `Admin` объявлены без модификатора видимости, то есть являются обычными параметрами: свойства с этими именами уже объявлены в родителе, и наследник только передаёт значения дальше. Если дочерний класс не объявляет конструктор, он наследует конструктор родителя, и вызывать его явно не нужно.

### Модификатор protected

Модификатор `protected` из таблицы видимости приобретает смысл только при наследовании. Защищённый член класса недоступен внешнему коду, но доступен методам наследников[^9]. Закрытый член, напротив, недоступен и наследникам. Рассмотрим упрощённый класс `User` с одним закрытым свойством:

```php
class User
{
    public function __construct(
        private string $email,
    ) {
    }
}

class Admin extends User
{
    public function contact(): string
    {
        return $this->email;   // Warning: Undefined property: Admin::$email
    }
}
```

Свойство `$email` принадлежит классу `User`, и для метода класса `Admin` его не существует. Если объявить свойство `protected`, метод `contact()` сможет его прочитать, а внешний код по-прежнему нет.

Модификатор `protected` неявно используется и для свойств `readonly`: начиная с PHP 8.4 их видимость записи равна `protected(set)`, поэтому инициализировать такое свойство может и конструктор наследника[^4].

Выбор между `private` и `protected` является решением о том, что класс открывает своим наследникам. Член `protected` становится частью договорённости между родителем и наследниками: его нельзя переименовать или изменить, не проверив все дочерние классы. Поэтому по умолчанию члены класса объявляют `private`, а `protected` используют, когда наследнику действительно нужен доступ.

## Полиморфизм

### Задача: уведомления

Почти любое веб-приложение сообщает пользователю о событиях:

- интернет-магазин подтверждает заказ,
- сервис бронирования напоминает о визите,
- университетский портал сообщает о новой оценке.

Каналы связи различаются:

- электронная почта,
- SMS,
- Telegram.

Какой канал использовать, пользователь выбирает в настройках профиля.

Задачу можно решить _функцией с ветвлением по названию канала_.

```php
function sendNotification(string $channel, string $to, string $text): void
{
    if ($channel === 'email') {
        echo 'Письмо на ' . $to . ': ' . $text . '<br>';
    } elseif ($channel === 'sms') {
        echo 'SMS на ' . $to . ': ' . mb_substr($text, 0, 70) . '<br>';
    } elseif ($channel === 'telegram') {
        echo 'Telegram, чат ' . $to . ': ' . $text . '<br>';
    }
}

sendNotification('email', 'client@example.com', 'Заказ №1024 оформлен');
sendNotification('sms', '+37369123456', 'Заказ №1024 оформлен');
```

Пока каналов два или три, функция выглядит приемлемо. С ростом приложения проявляются её недостатки:

- _Настройки всех каналов в одном месте_.
  - Для отправки письма нужны адрес почтового сервера и адрес отправителя.
  - Для SMS - ключ доступа к сервису.
  - Для Telegram - токен бота.

    Все эти значения приходится передавать в одну функцию или хранить в глобальных переменных.

- _Каждый новый канал требует изменять существующий код_. Чтобы добавить push-уведомления, нужно дописать ветку в `sendNotification()` и во все остальные функции, которые необходимо изменить при добавлении нового канала.
- _Ошибка в названии канала не обнаруживается_. Вызов `sendNotification('telegarm', ...)` не попадает ни в одну ветку: функция завершается без сообщений, а пользователь не получает уведомления.

### Один вызов, разное поведение

Вынесем каждый канал в отдельный класс. Настройки канала передаются в его конструктор, а отправку выполняет метод `send()` с одинаковой сигнатурой во всех классах.

```php
class EmailNotifier
{
    public function __construct(private string $from)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'Письмо от ' . $this->from . ' на ' . $to . ': ' . $text . '<br>';
    }
}

class SmsNotifier
{
    public function __construct(private string $apiKey)
    {
    }

    public function send(string $to, string $text): void
    {
        // ключ $this->apiKey понадобился бы при обращении к сервису отправки SMS
        echo 'SMS на ' . $to . ': ' . mb_substr($text, 0, 70) . '<br>';
    }
}

class TelegramNotifier
{
    public function __construct(private string $botToken)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'Telegram, чат ' . $to . ': ' . $text . '<br>';
    }
}
```

Теперь код, который подтверждает заказ, не знает о каналах ничего:

```php
function confirmOrder($notifier, string $to, int $orderId): void
{
    $notifier->send($to, 'Заказ №' . $orderId . ' оформлен');
}

confirmOrder(new EmailNotifier('shop@example.com'), 'client@example.com', 1024);
confirmOrder(new SmsNotifier('test-key'), '+37369123456', 1024);
confirmOrder(new TelegramNotifier('test-token'), '512345678', 1024);
// Письмо от shop@example.com на client@example.com: Заказ №1024 оформлен
// SMS на +37369123456: Заказ №1024 оформлен
// Telegram, чат 512345678: Заказ №1024 оформлен
```

В функции `confirmOrder()` записан один вызов `$notifier->send(...)`, но выполняется он по-разному: какая реализация `send()` сработает, определяется классом объекта, переданного в функцию. Функция говорит "отправь", а как отправить, решает сам объект.

**Полиморфизм (polymorphism)** - способность одного и того же кода работать с объектами разных классов, при которой выполняемая реализация метода определяется классом конкретного объекта.

Сравним с функцией `sendNotification()`:

- Настройки каждого канала хранятся в его объекте и передаются один раз, при создании.
- Новый канал - это новый класс. Функция `confirmOrder()` и весь остальной код, который отправляет уведомления, не меняется.
- Ошибка в имени класса приводит к ошибке `Class "X" not found` в той строке, где она допущена, вместо молчаливого отказа.

> [!NOTE]
>
> Выбор канала не исчезает полностью: где-то программа должна создать объект нужного класса по значению из настроек пользователя. Полиморфизм сводит этот выбор к одному месту, а весь остальной код работает с объектом, не проверяя его класс.

### Чего не хватает этому решению

Параметр `$notifier` в функции `confirmOrder()` объявлен без типа: общего типа у трёх классов нет. Функция примет любое значение, и о том, что у объекта есть метод `send()`, договорились только на словах.

Договорённость легко нарушить. Предположим, в проект добавили канал Viber, и его метод отправки назвали иначе:

```php
class ViberNotifier
{
    public function sendMessage(string $to, string $text): void
    {
        echo 'Viber на ' . $to . ': ' . $text . '<br>';
    }
}

confirmOrder(new ViberNotifier(), '+37369123456', 1024);
// Fatal error: Uncaught Error: Call to undefined method ViberNotifier::send()
```

Ошибка проявится не при написании класса, а при первом подтверждении заказа через Viber, то есть у пользователя. Нужен общий тип, который гарантирует наличие метода `send()` и который можно указать в объявлении параметра. В PHP есть два способа задать такой тип: абстрактный класс и интерфейс.

## Абстрактные классы

### Абстрактный класс и абстрактный метод

Первый способ решить вышеописанную проблему - родительский класс `Notifier`, от которого наследуются все каналы. Но что должен делать метод `send()` в самом родителе? Ответ прост: ничего. Родительский класс объявляет метод как абстрактный, а конкретная реализация предоставляется в наследниках.

**Абстрактный класс (abstract class)** - класс, объявленный с ключевым словом `abstract`, объект которого создать нельзя, он предназначен только для наследования[^19].

**Абстрактный метод (abstract method)** - метод, объявленный без тела, каждый неабстрактный наследник обязан его реализовать[^19].

_Синтаксис_

```php
abstract class ClassName
{
    abstract modifier function methodName(parameters): type;

    // обычные свойства и методы
}
```

- Класс, содержащий хотя бы один абстрактный метод, должен быть объявлен абстрактным.
- Абстрактный класс может содержать обычные свойства, методы и конструктор.
- Абстрактный метод может быть `public` или `protected`. Реализация в наследнике должна иметь совместимую сигнатуру (раздел "Переопределение методов").

_Пример_

```php
<?php

declare(strict_types=1);

abstract class Notifier
{
    abstract public function send(string $to, string $text): void;

    protected function format(string $text): string
    {
        return 'Shop: ' . $text;
    }
}

class EmailNotifier extends Notifier
{
    public function __construct(private string $from)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'Письмо от ' . $this->from . ' на ' . $to . ': ' . $this->format($text) . '<br>';
    }
}

class SmsNotifier extends Notifier
{
    public function __construct(private string $apiKey)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'SMS на ' . $to . ': ' . mb_substr($this->format($text), 0, 70) . '<br>';
    }
}

function confirmOrder(Notifier $notifier, string $to, int $orderId): void
{
    $notifier->send($to, 'Заказ №' . $orderId . ' оформлен');
}

confirmOrder(new EmailNotifier('shop@example.com'), 'client@example.com', 1024);
confirmOrder(new SmsNotifier('test-key'), '+37369123456', 1024);
// Письмо от shop@example.com на client@example.com: Shop: Заказ №1024 оформлен
// SMS на +37369123456: Shop: Заказ №1024 оформлен
```

В этом решении появились две вещи, которых не было в предыдущем разделе:

- _Гарантия_. Параметр `$notifier` объявлен с типом `Notifier`, и PHP примет только объект наследника этого класса. У каждого такого объекта обязательно есть метод `send()`.
- _Общий код_. Метод `format()` добавляет к тексту название магазина. Он написан один раз в родителе, а наследники вызывают его как `$this->format()`.

Метод `format()` объявлен `protected`: внешнему коду он не нужен, а наследникам нужен доступ, чтобы его вызвать.

При помощи абстрактного класса можно избежать ошибок, связанных с отсутствием методов в наследниках: PHP проверяет наличие всех абстрактных методов ещё на этапе объявления класса. В данном случае ошибка обнаруживается до того, как хоть один объект будет создан.

```php
class ViberNotifier extends Notifier
{
    public function sendMessage(string $to, string $text): void
    {
    }
}
// Fatal error: Class ViberNotifier contains 1 abstract method and must therefore
// be declared abstract or implement the remaining methods (Notifier::send)
```

Ошибка обнаруживается при загрузке файла с классом, до того как хоть один пользователь оформит заказ.

Создать объект самого абстрактного класса также нельзя:

```php
$notifier = new Notifier();
// Fatal error: Uncaught Error: Cannot instantiate abstract class Notifier
```

### Финальные классы и методы

Переопределение позволяет наследнику изменить любой метод родителя. Иногда это нежелательно: автор класса хочет, чтобы определённое поведение нельзя было изменить, или класс вообще не предназначен для наследования.

**Финальный метод (final method)** - метод, объявленный с ключевым словом `final`, который нельзя переопределить в дочерних классах. **Финальный класс (final class)** - класс, объявленный с ключевым словом `final`, от которого нельзя наследовать[^20].

_Синтаксис_

```php
final class ClassName
{
}

class ClassName
{
    final public function methodName(): type
    {
    }
}
```

- Попытка переопределить финальный метод или унаследовать финальный класс завершается фатальной ошибкой при объявлении класса.
- Начиная с PHP 8.1 `final` применяется и к константам класса, а начиная с PHP 8.4 - к свойствам[^20].

_Пример_

```php
final class EmailNotifier extends Notifier
{
    // ...
}

class HtmlEmailNotifier extends EmailNotifier
{
}
// Fatal error: Class HtmlEmailNotifier cannot extend final class EmailNotifier
```

Встроенные классы PHP используют тот же приём для методов. Метод `getMessage()` класса `Exception` объявлен финальным[^21], поэтому ни один класс исключения не может подменить способ получения сообщения.

Ключевое слово `final` выражает намерение автора класса. Финальный класс можно сделать нефинальным, когда появится обоснованная потребность в наследнике, а обратное изменение может сломать уже написанные дочерние классы. Поэтому классы, не предназначенные для наследования, часто объявляют финальными сразу.

## Наследование в веб-разработке

Наследование - механизм, который изучают одним из первых, но в прикладном коде веб-приложений его применяют ограниченно. Типичный случай - собственные классы исключений, построенные на встроенных `RuntimeException` или `InvalidArgumentException`. Общий тип для разных реализаций обычно задают интерфейсом (следующий раздел), а общий код выносят в отдельные классы, объекты которых используются через композицию (определение ниже).

Причины видны на примере уведомлений:

- _Родитель может быть только один_. Класс `SmsNotifier`, унаследованный от `Notifier`, уже не может унаследовать ничего другого, например готовый класс для работы с сервисом SMS.
- _Наследник жёстко связан с родителем_. Изменение метода `format()` в `Notifier` меняет поведение всех каналов сразу, а защищённые члены родителя становятся частью договорённости с наследниками (раздел "Модификатор protected").
- _Наследник получает всё_. Унаследовать можно только весь класс целиком, со всеми открытыми методами, даже если наследнику нужна их малая часть.

Наследование уместно, когда наследник действительно является частным случаем родителя и использует его поведение: администратор является пользователем. Если же класс нужен только ради повторного использования кода, применяют композицию.

**Композиция (composition)** - способ построения класса, при котором объект хранит другие объекты в своих свойствах и использует их методы.

Например, заказ содержит корзину, но не является корзиной. Если унаследовать класс заказа от класса корзины ради метода подсчёта суммы, у заказа появятся все открытые методы корзины, включая добавление товара, и товар можно будет добавить в уже оформленный заказ. При композиции заказ хранит корзину в закрытом свойстве и открывает только те действия, которые имеют смысл для заказа. Эту рекомендацию авторы классической книги о проектировании объектно-ориентированных программ сформулировали так: предпочитайте композицию наследованию[^22].

## Интерфейсы

### Та же задача через интерфейс

Вернёмся к уведомлениям. Функции `confirmOrder()` от класса `Notifier` нужно только одно: гарантия, что у объекта есть метод `send()` с определённой сигнатурой. Общий код `format()` полезен, но его можно вынести в отдельный класс и использовать через композицию, и гарантия от этого не пострадает.

> [!TIP]
>
> В примерах этого раздела `format()` опущен, чтобы не отвлекать от главного.

Для такой гарантии без общего кода и без единственного родителя в PHP есть отдельная конструкция.

**Интерфейс (interface)** - конструкция, объявляющая набор методов без тела, которые обязан содержать каждый класс, объявивший `implements` этого интерфейса[^23].

Интерфейс часто называют _контрактом_: класс, реализующий интерфейс, обязуется предоставить перечисленные методы, а код, который принимает интерфейс как тип, может на них рассчитывать.

_Синтаксис_

```php
interface InterfaceName
{
    public function methodName(parameters): type;
}

class ClassName implements InterfaceName
{
    public function methodName(parameters): type
    {
        // реализация
    }
}
```

- Все методы интерфейса открытые и не имеют тела[^23].
- Класс, реализующий интерфейс, обязан реализовать все его методы с совместимой сигнатурой. Пропущенный метод приводит к той же фатальной ошибке, что и нереализованный абстрактный метод.
- Создать объект интерфейса нельзя, но имя интерфейса можно использовать как тип параметра, результата и в операторе `instanceof`.
- Класс может реализовать несколько интерфейсов, перечислив их через запятую: `implements InterfaceA, InterfaceB`. Сочетание с наследованием записывается как `class ClassName extends ParentClass implements InterfaceName`.

_Пример_

```php
<?php

declare(strict_types=1);

interface Notifier
{
    public function send(string $to, string $text): void;
}

final class EmailNotifier implements Notifier
{
    public function __construct(private string $from)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'Письмо от ' . $this->from . ' на ' . $to . ': ' . $text . '<br>';
    }
}

final class SmsNotifier implements Notifier
{
    public function __construct(private string $apiKey)
    {
    }

    public function send(string $to, string $text): void
    {
        echo 'SMS на ' . $to . ': ' . mb_substr($text, 0, 70) . '<br>';
    }
}

function confirmOrder(Notifier $notifier, string $to, int $orderId): void
{
    $notifier->send($to, 'Заказ №' . $orderId . ' оформлен');
}

confirmOrder(new EmailNotifier('shop@example.com'), 'client@example.com', 1024);
confirmOrder(new SmsNotifier('test-key'), '+37369123456', 1024);
// Письмо от shop@example.com на client@example.com: Заказ №1024 оформлен
// SMS на +37369123456: Заказ №1024 оформлен
```

Функция `confirmOrder()` не изменилась ни на символ: тип параметра по-прежнему `Notifier`, только теперь это имя интерфейса, а не класса. Это тот же полиморфизм, что и в предыдущих разделах, но общий тип задан контрактом, а не родителем. Попытка передать объект, не реализующий интерфейс, завершается ошибкой `TypeError` в момент вызова, а класс, который объявил `implements Notifier`, но не реализовал `send()`, не будет объявлен вовсе.

### Почему интерфейсы используются чаще

В современном PHP-коде общий тип для взаимозаменяемых реализаций чаще всего задают интерфейсом. Это следует из свойств интерфейса.

_Класс не расходует единственного родителя_. Ограничение из раздела "Наследование в веб-разработке" снимается: класс `TelegramNotifier` может наследовать готовому классу для работы с Telegram и одновременно реализовывать `Notifier`.

_Класс может выполнять несколько контрактов_. Рассмотрим пример. SMS-сервисы, в отличие от электронной почты, платные: магазин пополняет баланс, и администратору важно вовремя узнать, что баланс заканчивается. Эту способность описывает отдельный интерфейс, и реализует его только платный канал:

```php
interface PaidChannel
{
    public function balance(): int;
}

final class SmsNotifier implements Notifier, PaidChannel
{
    // конструктор и send() как в предыдущем примере

    public function balance(): int
    {
        return 85;   // остаток в леях, в реальном приложении запрашивается у SMS-сервиса
    }
}

function balanceWarning(PaidChannel $channel): string
{
    return $channel->balance() < 100 ? 'Пополните баланс SMS-сервиса' : '';
}

echo balanceWarning(new SmsNotifier('test-key'));   // Пополните баланс SMS-сервиса
```

Для функции `confirmOrder()` объект `SmsNotifier` является `Notifier`, для панели администратора он является `PaidChannel`. Каждая функция видит только ту часть объекта, которая ей нужна.

_Реализацию легко заменить_. Во время разработки и проверки кода отправлять настоящие письма и SMS не следует: сообщения уйдут реальным людям, а SMS ещё и стоят денег. Поэтому вместо настоящего канала подставляют тестовую реализацию, которая только запоминает сообщения:

```php
final class FakeNotifier implements Notifier
{
    public private(set) array $sent = [];

    public function send(string $to, string $text): void
    {
        $this->sent[] = $to . ': ' . $text;
    }
}

$fake = new FakeNotifier();
confirmOrder($fake, 'client@example.com', 1024);

echo count($fake->sent) . '<br>';   // 1
echo $fake->sent[0];                // client@example.com: Заказ №1024 оформлен
```

Функция `confirmOrder()` отработала полностью, а ни одного сообщения не отправлено. Код, который выбирает реализацию, меняется в одном месте, остальное приложение об этом не знает.

_Классы не обязаны быть родственными_. `EmailNotifier`, `SmsNotifier` и `FakeNotifier` не имеют общего кода и общего родителя. Их объединяет только обещание реализовать `send()`, и большего коду, который отправляет уведомления, не требуется.

На схеме 6.2 сплошная стрелка обозначает наследование (`extends`), пунктирные - реализацию интерфейса (`implements`). Знаки `+` и `-` перед членами класса обозначают видимость `public` и `private`. Слева один класс является частным случаем другого и использует его код, справа независимые классы объединены только контрактом, причём `SmsNotifier` выполняет сразу два контракта.

### Абстрактный класс или интерфейс

Оба механизма задают общий тип для полиморфизма, но отвечают на разные вопросы. Абстрактный класс отвечает на вопрос "что общего в устройстве этих классов", интерфейс - на вопрос "что эти классы обещают уметь".

| Свойство             | Абстрактный класс                                                           | Интерфейс                                                                                                           |
| -------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| Что содержит         | Свойства, константы, конструктор, методы с реализацией и абстрактные методы | Объявления открытых методов и константы (начиная с PHP 8.4 также свойства, которые в этой главе не рассматриваются) |
| Сколько у класса     | Один родитель                                                               | Любое количество                                                                                                    |
| Видимость методов    | `public` или `protected`                                                    | Только `public`                                                                                                     |
| Связь между классами | Наследники одного семейства с общим кодом                                   | Классы могут быть никак не связаны между собой                                                                      |
| Пример из главы      | `Notifier` с общим методом `format()`                                       | `Notifier` и `PaidChannel`: только контракт                                                                         |

Таблица описывает свойства, а не достоинства и недостатки: свойство становится ограничением только для конкретной задачи. На практике общий тип начинают с интерфейса. Абстрактный класс добавляют, когда у нескольких реализаций действительно появляется общий код, причём он может реализовывать интерфейс, а не заменять его.

## Собираем вместе

Соберём страницу корзины MiniShop с итоговой суммой заказа. Она использует основные механизмы главы: асимметричную видимость остатка, исключения, константу класса и интерфейс. Интерфейс в этот раз описывает скидки: магазин проводит акции разных видов, и код подсчёта суммы должен работать с любой из них так же, как функция `confirmOrder()` работает с любым каналом уведомлений.

```php
<?php

declare(strict_types=1);

final class Product
{
    public const CURRENCY = 'лей';

    public function __construct(
        public readonly int $id,
        public readonly string $name,
        public private(set) int $price,
        public private(set) int $stock = 0,
    ) {
        if ($price < 0 || $stock < 0) {
            throw new InvalidArgumentException('Цена и остаток не могут быть отрицательными');
        }
    }
}

final class Cart
{
    // Ключ - код товара (свойство id), значение - ['product' => Product, 'quantity' => int]
    private array $items = [];

    public function add(Product $product, int $quantity = 1): void
    {
        if ($quantity <= 0) {
            throw new InvalidArgumentException('Количество должно быть положительным');
        }

        $inCart = $this->items[$product->id]['quantity'] ?? 0;
        $available = $product->stock - $inCart;

        if ($quantity > $available) {
            throw new RuntimeException(
                'Товар "' . $product->name . '" доступен в количестве ' . $available . ' шт.'
            );
        }

        $this->items[$product->id] = [
            'product' => $product,
            'quantity' => $inCart + $quantity,
        ];
    }

    public function getItems(): array
    {
        return $this->items;
    }

    public function total(): int
    {
        $total = 0;

        foreach ($this->items as $item) {
            $total += $item['product']->price * $item['quantity'];
        }

        return $total;
    }
}

interface Discount
{
    public function description(): string;

    public function amountFor(int $orderTotal): int;
}

final class PercentDiscount implements Discount
{
    public function __construct(private int $percent)
    {
        if ($percent <= 0 || $percent > 50) {
            throw new InvalidArgumentException('Процент скидки должен быть от 1 до 50');
        }
    }

    public function description(): string
    {
        return 'Скидка ' . $this->percent . '%';
    }

    public function amountFor(int $orderTotal): int
    {
        return intdiv($orderTotal * $this->percent, 100);
    }
}

final class FixedDiscount implements Discount
{
    public function __construct(
        private int $amount,
        private int $minOrderTotal,
    ) {
    }

    public function description(): string
    {
        return 'Скидка ' . $this->amount . ' ' . Product::CURRENCY . ' при заказе от '
            . $this->minOrderTotal . ' ' . Product::CURRENCY;
    }

    public function amountFor(int $orderTotal): int
    {
        return $orderTotal >= $this->minOrderTotal ? $this->amount : 0;
    }
}

function formatPrice(int $price): string
{
    return number_format($price, 0, ',', ' ') . ' ' . Product::CURRENCY;
}

$laptop = new Product(1, 'Ноутбук Lenovo IdeaPad 3', 14999, 3);
$mouse = new Product(2, 'Мышь Logitech M185', 299, 10);

$cart = new Cart();
$warning = null;

$cart->add($laptop);
$cart->add($mouse, 2);

try {
    $cart->add($laptop, 5);
} catch (RuntimeException $e) {
    $warning = $e->getMessage();
}

$discounts = [new PercentDiscount(5), new FixedDiscount(100, 1500)];

$subtotal = $cart->total();
$discountTotal = 0;

foreach ($discounts as $discount) {
    $discountTotal += $discount->amountFor($subtotal);
}

?>
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>MiniShop - корзина</title>
</head>
<body>
    <h1>Корзина</h1>

    <?php if ($warning !== null): ?>
        <p><?= htmlspecialchars($warning) ?></p>
    <?php endif; ?>

    <table>
        <?php foreach ($cart->getItems() as $item): ?>
            <tr>
                <td><?= htmlspecialchars($item['product']->name) ?></td>
                <td><?= $item['quantity'] ?> × <?= formatPrice($item['product']->price) ?></td>
            </tr>
        <?php endforeach; ?>
    </table>

    <p>Сумма: <?= formatPrice($subtotal) ?></p>

    <?php foreach ($discounts as $discount): ?>
        <p><?= htmlspecialchars($discount->description()) ?>: -<?= formatPrice($discount->amountFor($subtotal)) ?></p>
    <?php endforeach; ?>

    <p>К оплате: <?= formatPrice($subtotal - $discountTotal) ?></p>
</body>
</html>
```

Страница показывает предупреждение `Товар "Ноутбук Lenovo IdeaPad 3" доступен в количестве 2 шт.`, ноутбук и две мыши в корзине, сумму 15 597 лей, скидки 779 и 100 лей и итог 14 718 лей.

Разберём решения, принятые в этом коде:

- _Правила находятся в классах_. Страница не проверяет остаток и условия скидок. Она вызывает методы и реагирует на исключение.
- _Исключения различаются по классу_. Нехватка товара является ситуацией времени выполнения, поэтому `add()` выбрасывает `RuntimeException`, и страница перехватывает именно его. Исключение `InvalidArgumentException` о неверном количестве страница не перехватывает: количество задано в её коде, поэтому такое исключение означает ошибку программиста, и скрывать его не следует.
- _Корзина построена композицией_. Объект `Cart` хранит объекты `Product` и открывает только три действия: `add()`, `getItems()` и `total()`.
- _Остаток защищён без геттеров_. Корзина читает `$product->stock` и `$product->price` напрямую, а изменить их вне класса `Product` нельзя.
- _Скидки заменяемы_. Новая акция, например скидка по промокоду, добавляется новым классом, реализующим `Discount`, и новым элементом массива `$discounts`. Цикл подсчёта и шаблон страницы при этом не меняются.

Третий вызов `add()` не изменил корзину: метод выполняет все проверки до записи в `$items`, и исключение выбрасывается раньше, чем изменяется состояние. Исключение само по себе не отменяет уже выполненные действия, поэтому порядок "сначала проверить, затем изменить" важен для любого метода, изменяющего объект.

> [!NOTE]
> В этом примере все классы и страница находятся в одном файле. В реальных приложениях каждый класс размещают в отдельном файле: стандарт PSR-1 предполагает, что файл либо объявляет классы и функции, либо выполняет действия, но не то и другое одновременно[^2]. Подключение одного PHP-файла к другому рассматривается в одной из следующих глав.

## Типичные ошибки

### Обращение к свойству без $this

```php
public function getPrice(): int
{
    return $price;
    // Warning: Undefined variable $price
    // Fatal error: Uncaught TypeError: Product::getPrice(): Return value must be of type int, null returned
}
```

Переменная `$price` внутри метода является локальной переменной, а не свойством. Она не определена, её значение равно `null`, и PHP сообщает о несоответствии возвращаемого типа. Свойство объекта доступно только как `$this->price`.

### Знак $ после оператора ->

```php
echo $product->$name;   // ошибка: имя свойства берётся из переменной $name
echo $product->name;    // правильно
```

### Ожидание копии при присваивании объекта

```php
$discounted = $product;
$discounted->price = 9999;   // изменена цена исходного товара
```

Для получения независимой копии используется `clone`.

### Перехват Exception для ошибок PHP

```php
try {
    $product = new Product('Ноутбук', '14999');
} catch (Exception $e) {
    // не выполнится: при strict_types=1 выбрасывается TypeError,
    // а TypeError не входит в ветвь Exception
}
```

### Забытый вызов parent::\_\_construct()

```php
class Admin extends User
{
    public function __construct(string $name, string $email, private array $sections)
    {
        // конструктор User не вызван, свойства name и email не инициализированы
    }
}
```

Если наследник объявляет конструктор, конструктор родителя вызывается только явно: `parent::__construct(...)`.

### Общий блок catch перед частным

```php
try {
    $product = new Product(1, 'Ноутбук', -100);
} catch (Exception $e) {
    // перехватит и InvalidArgumentException
} catch (InvalidArgumentException $e) {
    // никогда не выполнится
}
```

Блоки `catch` проверяются по порядку, поэтому более конкретный класс указывается первым.

### Сужение доступа при переопределении

```php
class Admin extends User
{
    protected function describe(): string   // в родителе метод открытый
    {
        return 'Администратор';
    }
}
// Fatal error: Access level to Admin::describe() must be public (as in class User)
```

Переопределённый метод не может сузить доступ: код, вызывающий `describe()` у любого пользователя, перестал бы работать с этим наследником.

### Открытое свойство в обход правил

```php
class Product
{
    public int $stock = 0;   // любой код может записать -5
}
```

Свойство, изменения которого подчиняются правилам, объявляется `private` или `public private(set)`, а изменяется методами, проверяющими эти правила.

| Элемент                   | Синтаксис                                                  | Назначение                                         |
| ------------------------- | ---------------------------------------------------------- | -------------------------------------------------- |
| Объявление класса         | `class ClassName { }`                                      | Описание структуры и поведения объектов            |
| Создание объекта          | `new ClassName(arguments)`                                 | Новый экземпляр класса                             |
| Обращение к члену объекта | `$object->property`, `$object->method()`                   | Чтение свойства, вызов метода                      |
| `$this`                   | `$this->property`                                          | Текущий объект внутри метода                       |
| Конструктор               | `public function __construct(...)`                         | Инициализация нового объекта                       |
| Продвижение параметров    | `__construct(private int $price)`                          | Объявление и инициализация свойства в параметре    |
| Исключения                | `throw`, `try`, `catch`, `finally`                         | Сообщение об ошибке и её обработка                 |
| Модификаторы видимости    | `public`, `protected`, `private`                           | Ограничение доступа к членам класса                |
| Асимметричная видимость   | `public private(set) int $stock`                           | Открытое чтение, запись только внутри класса       |
| `readonly`                | `public readonly int $id`                                  | Однократное присваивание                           |
| Константа класса          | `const CONSTANT_NAME = value;`, `ClassName::CONSTANT_NAME` | Значение, общее для класса                         |
| `clone`                   | `$copy = clone $object`                                    | Поверхностная копия объекта                        |
| `?->`                     | `$object?->property`                                       | Обращение к члену с допуском `null`                |

| Интерфейс                 | `interface`, `implements`                                  | Контракт из открытых методов                       |

## Резюме

1. Класс в PHP объявляется ключевым словом `class`, объект создаётся оператором `new`, к членам объекта обращаются через `->` без знака `$` перед именем свойства.
2. Типизированное свойство без значения недоступно для чтения до инициализации, а динамические свойства начиная с PHP 8.2 устарели.
3. Внутри метода свойства доступны только через `$this`; продвижение параметров конструктора объявляет и инициализирует свойства в одной записи.
4. Ветви `Exception` и `Error` иерархии `Throwable` различны: `catch (Exception $e)` не перехватывает ошибки PHP вроде `TypeError`.
5. Асимметричная видимость `public private(set)` открывает свойство для чтения и закрывает для записи, а `readonly` допускает только однократное присваивание.
6. Переменная с объектом хранит идентификатор объекта, поэтому присваивание не создаёт копию; копию создаёт `clone`, а `==` и `===` сравнивают данные и идентичность.
7. Наследник принимается везде, где ожидается родитель; конструктор родителя при наличии собственного конструктора вызывается только явно через `parent::__construct()`.
8. Полиморфизм заменяет ветвление по названию варианта вызовом метода, реализация которого определяется классом объекта.
9. Абстрактный класс задаёт общий тип и общий код и требует от наследников реализовать абстрактные методы; `final` запрещает переопределение метода или наследование класса.
10. Интерфейс задаёт контракт из открытых методов, и класс может реализовать несколько интерфейсов, поэтому в веб-разработке общий тип чаще задают интерфейсом, а общий код переносят в отдельные объекты (композиция).
