## Ретроспектива

В главе 7 мы создали страницу оформления заказа в приложении MiniShop. Страница позволяет выбрать доставку и оплату и рассчитывает итог: для курьера и оплаты наличными получилось 806 лей. Все интерфейсы, классы, функции и HTML этой страницы находятся в одном файле `checkout.php`.

В прошлой главе, в разделе "Подключение файлов", мы познакомились с `include`, `require` и `require_once`. Эти конструкции позволяют вынести код в другой файл и подключить его там, где он нужен.

Теперь разделим приложение на файлы и организуем их по папкам. Затем настроим автозагрузку классов, разберём пространства имён, которые помогают избежать конфликтов имён, и стандарт PSR-4.

## Когда одного файла становится мало

Пока программа небольшая, один файл удобен: весь код находится перед глазами. Когда приложение растёт, работать с одним файлом становится сложнее.

В большом файле обычно смешан код разного назначения:

- классы и интерфейсы,
- вспомогательные функции,
- настройки,
- обработка запроса,
- HTML-разметка.

Из-за этого появляются типичные неудобства:

- _Часть кода нельзя использовать отдельно_. При подключении файла выполняется и код обработки запроса, и разметка. Если другой странице нужен только класс, приходится выносить его или копировать.
- _Нужное место трудно найти_. Чтобы изменить один элемент, приходится пролистывать код, который к нему не относится.
- _Двум разработчикам неудобно работать одновременно_. Они могут изменить одни и те же строки, и при объединении изменений придётся разрешать конфликты.
- _Логика смешана с разметкой_. Бизнес-правила и HTML-теги находятся рядом, хотя меняются по разным причинам.

Код можно разделить на файлы по назначению: классы, функции, настройки и разметку хранить отдельно. Тогда страница подключает только необходимые ей файлы.

_Пример_. Файл `checkout.php` из главы 7 занимает 314 строк:

| Что находится в файле  | Сколько        | Примеры                                           |
| ---------------------- | -------------- | ------------------------------------------------- |
| Интерфейсы             | 3              | `DeliveryMethod`, `CartItem`, `PaymentMethod`     |
| Абстрактный класс      | 1              | `RegularDelivery`                                 |
| Классы                 | 9              | `CourierDelivery`, `Cart`, `CashPayment`, `Order` |
| Функции                | 4              | `makeCart()`, `makeDelivery()`, `h()`             |
| Обработка формы и HTML | около 90 строк | `$_GET['delivery']`, `<form>`, `<table>`          |

Допустим, в приложении интернет-магазина нужна вторая страница - _Корзина_. Она использует классы `Cart` и `Product` и функцию `h()`, но ей не нужны доставка и оплата. Если подключить `checkout.php` целиком, вместе с объявлениями выполнится код страницы заказа и выведется её HTML. Если же скопировать нужные объявления в новый файл, изменения придётся вносить в обе копии.

## Структура проекта

Прежде чем разделить код, определим назначение папок. Это помогает быстрее находить нужный файл и отделяет файлы, доступные по адресам сайта, от настроек и частей страниц, которые подключаются только внутри приложения.

В проектах PHP часто используют такую структуру папок:

| Папка        | Что в ней лежит                  |
| ------------ | -------------------------------- |
| `public/`    | файлы, которые открывает браузер |
| `src/`       | функции и классы                 |
| `config/`    | настройки                        |
| `templates/` | общие части HTML-страниц         |
| `data/`      | учебные данные вместо базы данных |

Главное правило этой структуры - разделить файлы, которые открывает браузер, и файлы, которые только подключаются.

**Точка входа (entry point)** - файл, с которого начинается обработка запроса. Браузер запрашивает адрес, веб-сервер запускает файл точки входа, а тот подключает остальные файлы проекта.

**Корневая папка сайта (document root)** - папка, файлы которой веб-сервер отдаёт по адресам сайта. Всё, что лежит вне её, по URL недоступно. Корневой папкой сайта обычно делают `public/`. В ней размещают точки входа и доступные браузеру ресурсы, например CSS и изображения.

Встроенный веб-сервер PHP запускается командой, в которой задают корневую папку.

_Синтаксис_

```bash
php -S адрес:порт -t папка
```

- `адрес:порт` - где сервер принимает запросы, например `localhost:8000`.
- `-t папка` - корневая папка сайта. Без этого флага корневой становится папка, из которой запущен сервер[^1].

_Пример_. Учебный каталог MiniShop из папки `code/01_plain_split` устроен так:

```text
01_plain_split/
├── public/          файлы, которые открывает браузер
│   ├── catalog.php
│   └── delivery.php
├── src/             функции, а позже и классы
│   └── functions.php
├── config/          настройки магазина
│   └── shop.php
├── data/            учебные данные
│   └── products.php
└── templates/       общие части HTML-страниц
    ├── header.php
    └── footer.php
```

Точки входа здесь - `catalog.php` и `delivery.php`. Запустим сервер с корневой папкой `public/`:

```bash
cd 01_plain_split
php -S localhost:8000 -t public
```

Адрес `http://localhost:8000/catalog.php` открывает каталог. Адрес `http://localhost:8000/src/functions.php` возвращает код `404`: сервер ищет файл `public/src/functions.php` и не находит его.

Если запустить сервер без `-t public`, корневой папкой станет весь проект. Тогда каталог откроется только по адресу `/public/catalog.php`, а адрес `/templates/header.php` выполнит часть страницы отдельно, с предупреждениями о неизвестных переменных.

## Разделение обычного кода на файлы

Кроме классов, в проекте есть код другого рода. В отдельные файлы обычно выносят:

- функции, которые нужны нескольким страницам,
- настройки и данные,
- общие части HTML-страниц.

Такие файлы подключают уже знакомыми `require` и `require_once`. Путь к файлу строят от `__DIR__`, как объясняет раздел ["Пути к подключаемым файлам"](#пути-к-подключаемым-файлам): в файлах из `public/` запись `__DIR__ . '/..'` ведёт в папку проекта.

### Файл с функциями

Если одна и та же функция нужна нескольким страницам, её не объявляют в каждой из них: получатся копии, которые придётся править одновременно. Такие функции выносят в отдельный файл, например `src/functions.php`.

Правила для файла с функциями:

- _Файл только объявляет функции_. Он ничего не выводит и не обрабатывает запрос.
- _Файл подключают через `require_once`_. Если файл с функциями подключить дважды через `require`, PHP остановится с фатальной ошибкой: функция с таким именем уже объявлена[^2]. Конструкция `require_once` проверяет, подключался ли файл, и повторно его не подключает.

Повторное подключение случается чаще, чем кажется. Например, страница подключает файл функций, а затем другой файл, который тоже его подключает.

_Пример_. Функции MiniShop лежат в `src/functions.php`:

```php
<?php

declare(strict_types=1);

function h(string $text): string
{
    return htmlspecialchars($text, ENT_QUOTES, 'UTF-8');
}

function formatPrice(int $amount, string $currency): string
{
    return $amount . ' ' . $currency;
}
```

Страница приложения подключает файл одной строкой:

```php
require_once __DIR__ . '/../src/functions.php';
```

### Файл с настройками и данными

Значения, которые нужны разным страницам (название сайта, валюта, лимиты), хранят в одном файле настроек. Если записать их прямо в код страниц, при изменении придётся искать все места, где они встречаются. В отдельный файл так же выносят данные, например учебный список товаров.

Подключаемый файл может вернуть значение, и это значение станет результатом `require`[^2].

_Синтаксис_

```php
// подключаемый файл
return значение;

// файл, который подключает
$переменная = require 'путь/к/файлу.php';
```

- `return` завершает выполнение подключаемого файла и передаёт значение.
- `require` возвращает это значение, и его можно сохранить в переменную.
- Файл со значением подключают через `require`. Если файл уже подключался, `require_once` не выполняет его повторно и возвращает `true` вместо значения[^3].

_Пример_. Файл `config/shop.php` приложения MiniShop возвращает массив настроек:

```php
<?php

return [
    'shopName' => 'MiniShop',
    'currency' => 'лей',
    'freeDeliveryFrom' => 1000,
];
```

Страница получает этот массив в переменную:

```php
$config = require __DIR__ . '/../config/shop.php';

echo $config['freeDeliveryFrom']; // 1000
```

PHP выполняет `config/shop.php`, `return` передаёт массив, и тот попадает в `$config`. Значение `$config['freeDeliveryFrom']` равно `1000`.

Файл `data/products.php` устроен так же: он возвращает массив из трёх товаров. Когда в курсе появится база данных, товары будут храниться в ней.

### Общие части страницы

У страниц сайта обычно одинаковое начало и конец:

- заголовок с названием сайта,
- меню,
- подвал.

Если скопировать эту разметку в каждую страницу, изменение пункта меню придётся вносить везде. Общие части выносят в отдельные файлы, например `templates/header.php` и `templates/footer.php`.

Страница собирается по такой схеме:

```php
$title = 'Заголовок страницы';                 // переменные для частей страницы
require __DIR__ . '/../templates/header.php';  // начало страницы

// содержимое страницы

require __DIR__ . '/../templates/footer.php';  // конец страницы
```

Правила для частей страницы:

- _Переменные задают до подключения_. Подключённый код видит переменные из того места, где стоит `require`[^2].
- _Части подключают через `require`_. Одна и та же часть может понадобиться несколько раз, например карточка товара в цикле.

_Пример_. Начало страницы MiniShop в `templates/header.php`:

```php
<!doctype html>
<html lang="ru">
<head>
    <meta charset="utf-8">
    <title><?= h($title) ?> - <?= h($config['shopName']) ?></title>
</head>
<body>
    <h1><?= h($config['shopName']) ?></h1>
    <nav><a href="catalog.php">Каталог</a> | <a href="delivery.php">Доставка</a></nav>
    <h2><?= h($title) ?></h2>
```

Переменные `$title` и `$config` в `header.php` не объявлены. Их задаёт страница каталога до подключения:

```php
<?php

declare(strict_types=1);

require_once __DIR__ . '/../src/functions.php';
$config = require __DIR__ . '/../config/shop.php';
$products = require __DIR__ . '/../data/products.php';

$title = 'Каталог';
require __DIR__ . '/../templates/header.php';
?>
    <ul>
        <?php foreach ($products as $product): ?>
            <li><?= h($product['title']) ?> - <?= formatPrice($product['price'], $config['currency']) ?></li>
        <?php endforeach; ?>
    </ul>
<?php require __DIR__ . '/../templates/footer.php'; ?>
```

Сервер отправляет браузеру одну страницу: начало из `header.php`, список товаров и подвал из `footer.php`. Список выглядит так:

```text
Мышь Logitech M185 - 299 лей
Коврик для мыши - 89 лей
Подарочная упаковка - 49 лей
```

Цены берутся из `data/products.php`, а слово "лей" - из настройки `currency`. Вторая страница, `delivery.php`, подключает те же `header.php` и `footer.php` и выводит фразу "Бесплатная доставка от 1000 лей". Новый пункт меню появится на обеих страницах после правки одного файла.

## Пути к подключаемым файлам

**Текущая рабочая папка (current working directory)** - папка, из которой запущена программа. В терминале это папка, в которой вы набрали команду `php`.

Относительный путь вида `../src/functions.php` PHP отсчитывает не от файла, в котором написан `require`, а от текущей рабочей папки[^2]. Одна и та же программа, запущенная из разных папок, ищет файл в разных местах.

Надёжный путь строят от магической константы `__DIR__`. Она содержит папку текущего файла и не зависит от того, откуда запущена программа[^4].

_Синтаксис_

```php
require_once __DIR__ . '/путь/от/папки/файла.php';
```

- `__DIR__` - папка файла, в котором написан `require`.
- `/..` - переход на папку выше.
- Добавляемая часть пути начинается с `/`.

> [!NOTE]
> Значение `__DIR__` не заканчивается символом `/`[^4]. Если написать `__DIR__ . '../src/functions.php'`, получится путь вида `.../public../src/functions.php`, и файл не найдётся.

_Пример_. Страница `public/price.php` подключает файл функций из папки `src/`:

```php
<?php

declare(strict_types=1);

require_once __DIR__ . '/../src/functions.php';

echo formatPrice(299, 'лей') . "\n";
```

Программа выводит `299 лей` при обоих способах запуска: `php price.php` из папки `public` и `php public/price.php` из папки проекта. С путём `'../src/functions.php'` второй способ завершился бы ошибкой `Failed opening required`: переход `..` отсчитывался бы от папки проекта, а не от `public`.

## Классы в отдельных файлах

Классы тоже выносят в отдельные файлы. Странице больше не нужно подключать файл со всей разметкой, чтобы воспользоваться одним классом.

### Один класс - один файл

Стандарт PSR-1 задаёт три правила для файлов с классами[^5]:

- _Каждый класс, интерфейс и трейт находится в отдельном файле_.
- _Имя файла совпадает с именем класса_. Класс `User` лежит в файле `User.php`. Позже это правило позволит PHP находить файл класса по его имени.
- _Файл либо объявляет классы, функции и константы, либо выполняет действия, например выводит HTML_[^5]. Если файл класса что-то выводит, каждая страница, которая подключает этот класс, выведет тот же текст.

_Пример_. Файл `src/CourierDelivery.php` только объявляет класс:

```php
<?php

declare(strict_types=1);

class CourierDelivery extends RegularDelivery
{
    public function title(): string
    {
        return 'Курьер';
    }

    protected function baseCost(): int
    {
        return 50;
    }
}
```

После разделения три интерфейса и десять классов из `checkout.php`, включая абстрактный `RegularDelivery`, занимают 13 файлов.

### Порядок подключения классов

Когда классы подключают вручную, важен порядок. Чтобы объявить дочерний класс, PHP должен уже знать его родительский класс и интерфейсы, которые тот реализует. Поэтому файлы подключают в таком порядке:

1. Интерфейсы.
2. Родительские классы.
3. Дочерние классы.

Если нарушить порядок, PHP остановится с ошибкой `Class "..." not found` или `Interface "..." not found`.

_Пример_. Подключим классы доставки MiniShop. Интерфейс `DeliveryMethod` идёт первым, родительский `RegularDelivery` - вторым, дочерний `CourierDelivery` - последним:

```php
require_once __DIR__ . '/../src/DeliveryMethod.php';
require_once __DIR__ . '/../src/RegularDelivery.php';
require_once __DIR__ . '/../src/CourierDelivery.php';

$delivery = new CourierDelivery();

echo $delivery->title() . ': ' . $delivery->cost(736) . " лей\n";
// Курьер: 50 лей
```

Метод `cost()` из главы 7 получает сумму товаров и возвращает стоимость доставки. Сумма 736 лей меньше порога бесплатной доставки в 1000 лей, поэтому метод возвращает базовую стоимость курьера - 50 лей.

Ручное подключение работает, но с ростом проекта становится неудобным:

- каждая страница перечисляет все нужные файлы,
- порядок строк приходится поддерживать вручную,
- новый класс нужно добавить во все списки.

Для страницы заказа MiniShop пришлось бы подключить 13 файлов с классами и интерфейсами.

## Автозагрузка классов

Удобнее, чтобы PHP сам подключал файл класса в момент, когда тот впервые понадобился. Тогда страница не перечисляет файлы, а порядок перестаёт иметь значение.

**Автозагрузка (autoloading)** - механизм PHP, который при обращении к ещё не объявленному классу вызывает функцию программиста, чтобы та подключила нужный файл.

**Автозагрузчик (autoloader)** - функция, которая получает имя класса и подключает файл, где этот класс объявлен[^6].

Автозагрузка работает для классов, интерфейсов и трейтов[^6]. PHP вызывает автозагрузчик, когда класс нужен впервые:

- программа создаёт объект через `new`,
- программа обращается к статическому методу или константе класса,
- объявляемый класс ссылается на родителя или интерфейс.

### Функция `spl_autoload_register()`

Автозагрузчик регистрируют встроенной функцией `spl_autoload_register()`.

_Синтаксис_

```php
spl_autoload_register(?callable $callback = null, bool $throw = true, bool $prepend = false): bool
```

- `$callback` - автозагрузчик. Обычно это анонимная функция с одним параметром `string $class`. В этот параметр PHP передаёт имя класса, который нужно найти.
- `$throw` - с PHP 8.0 параметр не используется[^7].
- `$prepend` - если `true`, автозагрузчик ставится в начало очереди, а не в конец.

При успешной регистрации функция возвращает `true`. В PHP 8 некорректный аргумент приводит к исключению `TypeError`[^7].

Автозагрузчиков может быть несколько. PHP хранит их в очереди и вызывает по порядку регистрации, пока класс не будет объявлен[^7].

_Пример_. Автозагрузчик подключает файл из `src/` по имени класса:

```php
spl_autoload_register(function (string $class): void {
    require __DIR__ . '/../src/' . $class . '.php';
});

$delivery = new CourierDelivery();
// PHP вызывает функцию с $class = 'CourierDelivery'
// и подключает src/CourierDelivery.php
```

### Проверка файла перед подключением

Надёжный автозагрузчик проверяет, существует ли файл, прежде чем подключать его. Без проверки `require` несуществующего файла остановит программу с ошибкой `Failed opening required`, из которой непонятно, какого класса не хватило. С проверкой автозагрузчик при отсутствии файла ничего не делает. Тогда PHP вызывает следующий автозагрузчик из очереди, а если их больше нет, сообщает понятную ошибку `Class "..." not found`.

Для проверки служит встроенная функция `file_exists()`.

_Синтаксис_

```php
file_exists(string $filename): bool
```

- `$filename` - путь к файлу или папке.

Функция возвращает `true`, если файл или папка существует, и `false` в остальных случаях[^8].

_Пример_. Все 13 файлов классов MiniShop лежат в папке `src/`. Автозагрузчик проверяет, существует ли файл, выводит имя класса и подключает файл:

```php
<?php

declare(strict_types=1);

spl_autoload_register(function (string $class): void {
    if (file_exists(__DIR__ . '/../src/' . $class . '.php')) {
        echo "Автозагрузчик ищет класс $class\n";
        require __DIR__ . '/../src/' . $class . '.php';
    }
});

$delivery = new CourierDelivery();

echo $delivery->title() . ': ' . $delivery->cost(736) . " лей\n";
```

Программа выводит:

```text
Автозагрузчик ищет класс CourierDelivery
Автозагрузчик ищет класс RegularDelivery
Автозагрузчик ищет класс DeliveryMethod
Курьер: 50 лей
```

Разберём вывод по строкам:

1. `new CourierDelivery()` обращается к классу, которого PHP ещё не знает. PHP вызывает автозагрузчик с `$class = 'CourierDelivery'`, и тот подключает `src/CourierDelivery.php`.
2. В этом файле объявлен класс `CourierDelivery extends RegularDelivery`. Родителя PHP тоже не знает и снова вызывает автозагрузчик, теперь с `'RegularDelivery'`.
3. В `RegularDelivery.php` написано `implements DeliveryMethod`. Третий вызов подключает интерфейс.
4. Все три объявления готовы, объект создан, и программа выводит стоимость доставки: 50 лей.

PHP сам выстроил правильный порядок объявления: интерфейс, родитель, наследник.

### Чего автозагрузка не делает

У автозагрузки два ограничения:

- _Функции автозагрузчик не подключает_. Если вызвать функцию, которой нет, PHP сразу сообщит об ошибке и автозагрузчик не вызовет. Файл с функциями по-прежнему подключают через `require_once`.
- _Имя файла должно соответствовать правилу автозагрузчика_. В нашем примере для класса `Cart` автозагрузчик ищет `Cart.php`. Если файл назван `cart.php`, на Windows и macOS программа обычно работает: их файловые системы по умолчанию не различают регистр букв. На сервере с Linux, где регистр различается, та же программа сообщит `Class "Cart" not found`.

Пока все классы называются по-разному, плоской папки `src/` хватает. Но в такой схеме класс отличает от других только имя, и два класса с одним именем PHP различить не сможет.

## Пространства имён

### Конфликт имён

Одинаковые имена особенно часто встречаются в чужом коде: в библиотеках есть классы с распространёнными именами вроде `Validator`, `Logger` или `Request`. Если в программе объявлены два класса с одним именем, PHP останавливается с ошибкой `Cannot redeclare class`.

Переименование может устранить конкретный конфликт, но при использовании библиотек оно неудобно:

- _Изменение чужого кода трудно поддерживать_. При обновлении библиотеки правка может пропасть. Так же и при конфликте двух чужих библиотек: менять придётся код одной из них.
- _Каждая библиотека занимает новые имена_. Свои классы придётся переименовывать снова и снова.

Нужен способ различать классы с одинаковыми именами, не переименовывая их.

**Пространство имён (namespace)** - именованная группа классов, интерфейсов, трейтов, функций и констант[^9]. Имя элемента внутри группы может совпадать с именем в другой группе, и конфликта не будет. Это похоже на файлы: два файла с одним именем могут лежать в разных папках.

_Пример_. В MiniShop есть класс `Validator`, который проверяет количество товара: от 1 до 10, как в форме из главы 9. Приложению понадобилась учебная библиотека `SimpleMail` для отправки писем. В ней тоже есть класс `Validator`, только он проверяет адрес почты. Страница подключает оба файла:

```php
require_once __DIR__ . '/../src/Validator.php';
require_once __DIR__ . '/../lib/SimpleMail/Validator.php';
```

PHP 8.4 останавливается на втором подключении:

```text
Fatal error: Cannot redeclare class Validator (previously declared in .../src/Validator.php:5)
```

### Объявление пространства имён

_Синтаксис_

```php
<?php

declare(strict_types=1);

namespace Часть1\Часть2;

class ИмяКласса
{
}
```

Правила объявления:

- `namespace` стоит в начале файла. Перед ним может быть только конструкция `declare`[^10].
- Части имени разделяет обратная косая черта `\`, как папки в пути.
- Все классы, объявленные в файле после `namespace`, попадают в это пространство имён.

После объявления у класса два имени:

- **Полное имя класса (fully qualified name)** - имя класса вместе с пространством имён и ведущей `\`, например `\Shop\Form\Validator`. По полному имени к классу можно обратиться из любого файла.
- **Короткое имя (unqualified name)** - имя класса без пространства имён, например `Validator`. К короткому имени PHP добавляет текущее пространство имён файла[^11]. Например, в файле с `namespace Shop\Form` запись `new Validator()` означает `new \Shop\Form\Validator()`. Исключение составляют короткие имена из `use`, о них речь пойдёт в следующем подразделе.

_Пример_. Поместим два класса `Validator` в разные пространства имён. Класс магазина:

```php
<?php

declare(strict_types=1);

namespace MiniShop\Form;

class Validator
{
    public static function isQuantity(int $quantity): bool
    {
        return $quantity >= 1 && $quantity <= 10;
    }
}
```

Класс библиотеки:

```php
<?php

declare(strict_types=1);

namespace SimpleMail;

class Validator
{
    public static function isEmail(string $email): bool
    {
        return filter_var($email, FILTER_VALIDATE_EMAIL) !== false;
    }
}
```

Теперь это два разных класса: `MiniShop\Form\Validator` и `SimpleMail\Validator`. К классу библиотеки можно обратиться по полному имени:

```php
var_dump(\SimpleMail\Validator::isEmail('buyer@')); // bool(false)
```

Адрес `buyer@` не содержит домена, поэтому метод возвращает `false`.

### Оператор `use` и псевдонимы

Писать полное имя при каждом обращении долго. Оператор `use` позволяет обращаться к классу из другого пространства имён по короткому имени.

**Импорт (import)** - запись `use`, после которой класс доступен в файле по короткому имени[^12].

**Псевдоним (alias)** - второе имя класса в файле, которое задают словом `as`. Псевдоним нужен, если короткие имена двух классов совпадают[^12].

_Синтаксис_

```php
use Полное\Имя\Класса;
use Полное\Имя\Класса as Псевдоним;
```

Правила для `use`:

- _Имя в `use` всегда считается полным_, даже без ведущей `\`[^11].
- _`use` пишут в начале файла_, после `namespace`, если он есть.
- _`use` действует только в том файле, где написан_[^12]. Подключённый файл его не видит, и там `use` нужно написать заново.
- _`use` не подключает файл_. Он только сокращает имя, а файл по-прежнему подключает `require_once` или автозагрузчик.

_Пример_. Страница `public/order.php` использует оба класса `Validator`:

```php
require_once __DIR__ . '/../src/Form/Validator.php';
require_once __DIR__ . '/../lib/SimpleMail/Validator.php';

use MiniShop\Form\Validator;
use SimpleMail\Validator as MailValidator;

var_dump(Validator::isQuantity(2));                  // bool(true)
var_dump(MailValidator::isEmail('buyer@example.com')); // bool(true)
```

В этом файле `Validator` означает класс магазина, а `MailValidator` - класс библиотеки. Первый вызов возвращает `true`, потому что 2 входит в диапазон от 1 до 10. Второй возвращает `true`, потому что у адреса есть имя, `@` и домен.

### Классы из глобального пространства имён

**Глобальное пространство имён (global namespace)** - пространство, в котором находится код без объявления `namespace`[^13]. Там же находятся встроенные классы PHP, например `InvalidArgumentException` или `DateTime`.

Внутри пространства имён PHP добавляет текущее пространство имён и к короткому имени встроенного класса. Класса с полученным именем нет, и PHP сообщает `Class "..." not found`. В глобальное пространство имён PHP для классов сам не заглядывает[^13].

Встроенный класс внутри пространства имён записывают одним из двух способов.

_Синтаксис_

```php
throw new \InvalidArgumentException('...');   // полное имя с ведущей \

use InvalidArgumentException;                  // импорт в начале файла
throw new InvalidArgumentException('...');     // короткое имя
```

Встроенные функции внутри пространства имён работают без `\`. Для функций и констант PHP сначала ищет имя в текущем пространстве имён, а если не находит, берёт глобальную функцию или константу[^14].

_Пример_. Корзина MiniShop помещена в пространство имён `MiniShop\Cart`, а метод `add()` остался без изменений:

```php
<?php

declare(strict_types=1);

namespace MiniShop\Cart;

class Cart
{
    private array $items = [];

    public function add(CartItem $item, int $quantity = 1): void
    {
        if ($quantity <= 0) {
            throw new InvalidArgumentException('Количество должно быть положительным');
        }

        $this->items[] = ['item' => $item, 'quantity' => $quantity];
    }

    // методы items() и total() не изменились
}
```

Для `CartItem` в файле нет `use`: этот класс лежит в том же пространстве имён `MiniShop\Cart`, и короткое имя `CartItem` означает `MiniShop\Cart\CartItem`.

Этот код содержит ошибку. При добавлении товара с количеством `0` вместо сообщения о неверном количестве появляется фатальная ошибка:

```text
Fatal error: Uncaught Error: Class "MiniShop\Cart\InvalidArgumentException" not found in .../src/Cart/Cart.php:14
```

PHP добавил к короткому имени `InvalidArgumentException` пространство имён `MiniShop\Cart`, а такого класса нет. В исправленной версии `code/10_global_class_fixed` написано `\InvalidArgumentException`, и страница выводит `Ошибка: Количество должно быть положительным`. Функция `filter_var()` в классе `SimpleMail\Validator` работает без `\`: для функций PHP сам заглядывает в глобальное пространство имён.

## Стандарт PSR-4

### Как имя класса превращается в путь

Когда у классов есть пространства имён, файлы удобно раскладывать по подпапкам, соответствующим частям их имён. Простое правило "папка `src/`, имя класса и `.php`" для этого не подходит: оно вставило бы в имя файла полное имя с `\`, а не путь с подпапками. Автозагрузчик получает полное имя без ведущей `\`[^7] и должен превратить его в путь к файлу. Для такого превращения есть стандарт, который поддерживает Composer - менеджер зависимостей PHP, о котором пойдёт речь в главе 11[^15].

**PSR-4** - стандарт, который описывает, как по полному имени класса найти файл с этим классом[^16]. Его публикует PHP-FIG - группа разработчиков PHP-проектов, которая выпускает стандарты PSR. В стандарте два основных понятия:

- **Префикс пространства имён (namespace prefix)** - начальная часть полного имени, общая для классов проекта, например `App\`.
- **Базовая папка (base directory)** - папка, которая соответствует префиксу, например `src/`.

_Правило_

```text
Префикс\Часть\ИмяКласса  ->  базовая_папка/Часть/ИмяКласса.php
```

Правило применяется в три шага[^16]:

1. Префикс заменяется базовой папкой.
2. Оставшиеся части пространства имён становятся подпапками: каждая `\` превращается в `/`.
3. К имени класса добавляется `.php`. Регистр букв в папках и файле совпадает с регистром в имени класса.

При такой организации файлов легко допустить две ошибки:

- _Пространство имён не совпадает с папкой_. Автозагрузчик ищет файл в подпапке с именем части пространства имён. Если файл лежит в другой папке, он не найдётся.
- _Регистр не совпадает_. Папка названа `delivery/`, а часть пространства имён - `Delivery`. Как и в разделе ["Чего автозагрузка не делает"](#чего-автозагрузка-не-делает), на Linux такой файл не найдётся.

_Пример_. В MiniShop префикс - `MiniShop\`, а базовая папка - `src/`. Классы лежат так:

| Полное имя класса                   | Префикс     | Базовая папка | Файл                               |
| ----------------------------------- | ----------- | ------------- | ---------------------------------- |
| `MiniShop\Delivery\CourierDelivery` | `MiniShop\` | `src/`        | `src/Delivery/CourierDelivery.php` |
| `MiniShop\Cart\Cart`                | `MiniShop\` | `src/`        | `src/Cart/Cart.php`                |
| `MiniShop\Payment\CashPayment`      | `MiniShop\` | `src/`        | `src/Payment/CashPayment.php`      |
| `MiniShop\Order`                    | `MiniShop\` | `src/`        | `src/Order.php`                    |

В первой строке префикс `MiniShop\` заменяется на `src/`, часть `Delivery\` становится подпапкой `Delivery/`, а `CourierDelivery` - файлом `CourierDelivery.php`. У класса `Order` после префикса осталось только имя, поэтому его файл лежит прямо в `src/`.

### Автозагрузчик по правилам PSR-4

Автозагрузчик по правилам PSR-4 выполняет три действия:

1. Проверяет, начинается ли имя класса с префикса проекта. Если нет, сразу завершает работу: этот класс может найти другой автозагрузчик из очереди.
2. Отрезает префикс и заменяет в оставшейся части каждую `\` на `/`.
3. Добавляет спереди базовую папку, а в конце `.php` и подключает файл, если он существует.

Для первого шага нужна встроенная функция `str_starts_with()`.

_Синтаксис_

```php
str_starts_with(string $haystack, string $needle): bool
```

- `$haystack` - строка, в которой ищут.
- `$needle` - начало, которое проверяют.

Функция появилась в PHP 8.0. Она возвращает `true`, если `$haystack` начинается с `$needle`, и `false` в остальных случаях. Регистр букв учитывается[^17].

Для второго шага нужны функции из главы 5:

- `strlen($string)` возвращает длину строки,
- `substr($string, $offset)` возвращает часть строки начиная с позиции `$offset`,
- `str_replace($search, $replace, $subject)` заменяет в `$subject` все вхождения `$search` на `$replace`.

_Пример_. Автозагрузчик MiniShop основан на примере из документации PHP-FIG[^18] и лежит в файле `code/11_minishop/autoload.php`:

```php
<?php

declare(strict_types=1);

spl_autoload_register(function (string $class): void {
    $prefix = 'MiniShop\\';
    $baseDir = __DIR__ . '/src/';

    if (!str_starts_with($class, $prefix)) {
        return;
    }

    $relativeClass = substr($class, strlen($prefix));
    $file = $baseDir . str_replace('\\', '/', $relativeClass) . '.php';

    if (file_exists($file)) {
        require $file;
    }
});
```

Проследим, как автозагрузчик обрабатывает `MiniShop\Delivery\CourierDelivery`:

1. Имя начинается с `MiniShop\`, `str_starts_with()` возвращает `true`, и проверка пропускает класс дальше.
2. `strlen($prefix)` равно `9`: в строке `MiniShop\` девять символов. `substr($class, 9)` отрезает префикс. В `$relativeClass` остаётся `Delivery\CourierDelivery`.
3. `str_replace()` превращает `\` в `/`, и получается `Delivery/CourierDelivery`.
4. К базовой папке добавляются `Delivery/CourierDelivery` и `.php`. Получается путь `.../11_minishop/src/Delivery/CourierDelivery.php`.
5. Файл существует, и `require` его подключает.

Если имя класса начинается не с `MiniShop\`, например `SimpleMail\Validator`, автозагрузчик сразу выходит через `return`.

Две детали кода:

- _Путь без `/..`_. Файл `autoload.php` лежит в корне проекта, рядом с папкой `src/`, поэтому `$baseDir` равен `__DIR__ . '/src/'`.
- _Двойная `\` в строках_. Внутри строки `\` служит экранирующим символом: одиночная `\` перед закрывающей кавычкой экранировала бы саму кавычку. Документация PHP советует всегда удваивать `\` в именах внутри строк[^19], поэтому префикс записан как `'MiniShop\\'`.

В главе 11 этот автозагрузчик заменит Composer. В файле `composer.json` достаточно указать пару "префикс - папка", например `"MiniShop\\": "src/"`, и Composer сам создаст автозагрузчик по правилам PSR-4[^15].

## MiniShop: страница заказа из нескольких файлов

Применим разобранные приёмы к странице оформления заказа:

- точка входа лежит в `public/`,
- классы разложены по пространствам имён и папкам по правилам PSR-4,
- автозагрузчик заменяет список `require` для классов,
- функции и HTML лежат в отдельных файлах.

_Пример_. В `code/11_minishop` страница оформления заказа из главы 7 разложена по файлам:

```text
11_minishop/
├── autoload.php                  автозагрузчик PSR-4
├── public/
│   └── checkout.php              точка входа
├── src/
│   ├── Cart/
│   │   ├── Cart.php
│   │   ├── CartItem.php
│   │   └── Product.php
│   ├── Delivery/
│   │   ├── CourierDelivery.php
│   │   ├── DeliveryMethod.php
│   │   ├── ExpressDelivery.php
│   │   ├── PickupDelivery.php
│   │   ├── PostDelivery.php
│   │   └── RegularDelivery.php
│   ├── Payment/
│   │   ├── CardPayment.php
│   │   ├── CashPayment.php
│   │   └── PaymentMethod.php
│   ├── Order.php
│   └── functions.php             makeCart(), makeDelivery(), makePayment(), h()
└── templates/
    └── checkout.php              HTML страницы
```

Классы распределены по пространствам имён, соответствующим папкам: `MiniShop\Cart`, `MiniShop\Delivery`, `MiniShop\Payment`. Класс `Order` лежит прямо в `src/` и находится в пространстве имён `MiniShop`. Он использует классы из других пространств имён, поэтому в его файле есть `use`:

```php
<?php

declare(strict_types=1);

namespace MiniShop;

use MiniShop\Cart\Cart;
use MiniShop\Delivery\DeliveryMethod;
use MiniShop\Payment\PaymentMethod;

class Order
{
    // тело класса не изменилось
}
```

Функции остались в глобальном пространстве имён, чтобы страница вызывала их без `use`. В файле `src/functions.php` перед функциями стоят `use` для всех классов и интерфейсов, которые эти функции создают и возвращают. Без них PHP искал бы класс `Cart` для `new Cart()` в глобальном пространстве имён: `use` из других файлов здесь не действуют.

Точка входа `public/checkout.php` подключает два файла и обрабатывает форму:

```php
<?php

declare(strict_types=1);

require_once __DIR__ . '/../autoload.php';
require_once __DIR__ . '/../src/functions.php';

use MiniShop\Order;

// массивы $deliveryOptions и $paymentOptions - как в главе 7

$deliveryCode = $_GET['delivery'] ?? 'courier';
$paymentCode = $_GET['payment'] ?? 'cash';
$error = '';
$order = null;

try {
    if (!is_string($deliveryCode) || !is_string($paymentCode)) {
        throw new InvalidArgumentException('Некорректные параметры формы');
    }

    $order = new Order(makeCart(), makeDelivery($deliveryCode), makePayment($paymentCode));
} catch (InvalidArgumentException $exception) {
    http_response_code(400);
    $error = $exception->getMessage();
}

require __DIR__ . '/../templates/checkout.php';
```

Что изменилось по сравнению с главой 7:

1. Страница не содержит ни одного класса. Вместо 13 объявлений в ней две строки `require_once`: автозагрузчик и функции.
2. Логика выбора и HTML разделены. Точка входа готовит переменные `$order`, `$error`, `$deliveryCode`, `$paymentCode` и массивы вариантов. Файл `templates/checkout.php` их выводит: подключённый файл видит переменные точки входа, как `header.php` в разделе ["Общие части страницы"](#общие-части-страницы).
3. Запись `InvalidArgumentException` здесь работает без `\`: в файле нет `namespace`, и код находится в глобальном пространстве имён.

Запустим страницу:

```bash
cd 11_minishop
php -S localhost:8000 -t public
```

По адресу `http://localhost:8000/checkout.php` откроется та же форма, что в главе 7. Итоги для разных вариантов:

| Доставка          | Оплата   | Итог    |
| ----------------- | -------- | ------- |
| курьер            | наличные | 806 лей |
| экспресс-доставка | наличные | 876 лей |
| самовывоз         | карта    | 736 лей |

Числа совпадают с результатами главы 7: мы изменили организацию файлов, но не правила расчёта.

Странице "Корзина" из раздела ["Когда одного файла становится мало"](#когда-одного-файла-становится-мало) теперь достаточно подключить `autoload.php` и `src/functions.php` (ради функции `h()`). Классы она импортирует строками `use MiniShop\Cart\Cart;` и `use MiniShop\Cart\Product;`. Классы доставки и оплаты не подключатся, пока страница к ним не обратится.

## Резюме

- Код проекта делят на файлы по назначению: функции, настройки, данные, части страниц и классы.
- Браузеру доступна только папка `public/` с точками входа, остальной код лежит вне её.
- Файл может вернуть значение через `return`; такой файл подключают через `require`.
- Путь к подключаемому файлу строят от `__DIR__`, тогда он не зависит от папки запуска.
- Автозагрузчик, зарегистрированный через `spl_autoload_register()`, подключает файл класса при первом обращении к нему, поэтому порядок файлов не важен.
- Пространство имён позволяет двум классам с одинаковым коротким именем существовать в одной программе; `use` сокращает полное имя.
- Внутри пространства имён встроенные классы пишут с ведущей `\` или импортируют через `use`.
- PSR-4 связывает полное имя класса с путём к файлу: префикс - базовая папка, `\` - `/`, имя класса - файл `.php`.
