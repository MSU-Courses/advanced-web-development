## Полиморфизм

### Задача: способы доставки

MiniShop предлагает три способа доставки:

- курьер стоит 50 лей,
- почта стоит 35 лей,
- самовывоз бесплатен.

Для этих трёх способов доставка бесплатна при сумме заказа от 1000 лей. Страница оформления должна показать название и стоимость выбранной доставки. Пока можно решить задачу двумя функциями с `match`, которые выбирают вариант по строковому коду:

```php
<?php

declare(strict_types=1);

function deliveryTitle(string $code): string
{
    return match ($code) {
        'courier' => 'Курьер',
        'pickup' => 'Самовывоз',
        'post' => 'Почта Молдовы',
    };
}

function deliveryCost(string $code, int $orderTotal): int
{
    if ($code === 'pickup') {
        return 0;
    }

    if ($orderTotal >= 1000) {
        return 0;
    }

    return match ($code) {
        'courier' => 50,
        'post' => 35,
    };
}

echo deliveryTitle('courier') . ': ' . deliveryCost('courier', 600) . ' лей<br>';   // Курьер: 50 лей
echo deliveryTitle('post') . ': ' . deliveryCost('post', 1200) . ' лей<br>';        // Почта Молдовы: 0 лей
```

Для трёх способов такой код подходит, но при расширении магазина возникнут проблемы:

- _Данные разбросаны_. Название курьера находится в `deliveryTitle()`, стоимость - в `deliveryCost()`. Для срока доставки потребуется ещё одна функция с `match`.
- _Новый способ добавляется в нескольких местах_. Если забыть ветвь `match` в одной из функций, при выполнении может возникнуть `UnhandledMatchError`.
- _Опечатка обнаруживается поздно_. `deliveryCost('curier', 600)` завершится с `UnhandledMatchError`. При заказе от 1000 лей ошибка даже останется незамеченной: функция вернёт `0` до проверки кода.

### Понятие полиморфизма

Опишем каждый способ доставки отдельным классом. Все три класса имеют методы с одинаковыми именами и параметрами: `title()` и `cost()`.

```php
class CourierDelivery
{
    public function title(): string
    {
        return 'Курьер';
    }

    public function cost(int $orderTotal): int
    {
        return $orderTotal >= 1000 ? 0 : 50;
    }
}

class PickupDelivery
{
    public function title(): string
    {
        return 'Самовывоз';
    }

    public function cost(int $orderTotal): int
    {
        return 0;
    }
}

class PostDelivery
{
    public function title(): string
    {
        return 'Почта Молдовы';
    }

    public function cost(int $orderTotal): int
    {
        return $orderTotal >= 1000 ? 0 : 35;
    }
}

$deliveries = [new CourierDelivery(), new PickupDelivery(), new PostDelivery()];

foreach ($deliveries as $delivery) {
    echo $delivery->title() . ': ' . $delivery->cost(600) . ' лей<br>';
}
// Курьер: 50 лей
// Самовывоз: 0 лей
// Почта Молдовы: 35 лей
```

Цикл один, но `$delivery->cost(600)` выполняет метод того класса, объект которого сейчас находится в `$delivery`. Поэтому для курьера, самовывоза и почты результат различается (схема 7.1).

```text
$delivery->cost(600)
    │
    ├── в $delivery объект CourierDelivery ──► CourierDelivery::cost() ──► 50
    ├── в $delivery объект PickupDelivery  ──► PickupDelivery::cost()  ──► 0
    └── в $delivery объект PostDelivery    ──► PostDelivery::cost()    ──► 35
```

_Схема 7.1. Один вызов выполняет метод того класса, которому принадлежит объект_

Похожий механизм встречался в главе 6: функция `orderSummary()` по-разному приветствовала обычного и постоянного покупателя.

**Полиморфизм (polymorphism)** - возможность вызывать один и тот же метод у объектов разных классов, получая поведение, определённое их реализациями.

Теперь для нового способа доставки достаточно создать ещё один класс. Цикл менять не придётся.

### Вызов без общего типа

Но пока параметр `$delivery` не имеет типа. В функцию можно передать даже объект без методов `title()` и `cost()`:

```php
function deliveryLine($delivery, int $orderTotal): string
{
    return $delivery->title() . ': ' . $delivery->cost($orderTotal) . ' лей';
}

echo deliveryLine(new CourierDelivery(), 600) . '<br>';   // Курьер: 50 лей
echo deliveryLine(new Product('Мышь', 299), 600);
// Fatal error: Uncaught Error: Call to undefined method Product::title()
```

В этом примере `Product` - класс товара без методов `title()` и `cost()` (полный код: [03_no_common_type.php](code/03_no_common_type.php)). Неверный объект передали в `deliveryLine()`, но ошибка возникла позднее, внутри самой функции.

Чтобы решить эту проблему, всем способам доставки нужен общий тип. Из главы 6 нам знаком один вариант - общий родительский класс.

## Абстрактные классы

### Абстрактный класс и абстрактный метод

Назовём общего родителя `Delivery`. Но какую стоимость должен возвращать его `cost()`? Доставки "вообще" не существует, а заглушка `return 0;` опасна: новый наследник может забыть переопределить метод, и доставка ошибочно станет бесплатной. Нужен класс, который объявляет обязательные методы, но не задаёт им реализацию.

**Абстрактный класс (abstract class)** - класс, объявленный с ключевым словом `abstract`, объект которого создать нельзя. Он служит общим родителем для других классов[^1].

**Абстрактный метод (abstract method)** - метод, объявленный в абстрактном классе без тела. Каждый неабстрактный наследник обязан его реализовать[^1].

_Синтаксис_

```php
abstract class ClassName
{
    abstract modifier function methodName(type $parameter): type;

    modifier function otherMethod(): type
    {
        // обычный метод с реализацией
    }
}
```

- Абстрактный метод записывается без фигурных скобок, после списка параметров и типа результата ставится точка с запятой.
- Класс, в котором есть хотя бы один абстрактный метод, должен быть объявлен абстрактным.
- Наследник должен реализовать все абстрактные методы родителя или сам быть объявлен абстрактным.
- Абстрактный метод может быть только открытым или защищённым (`public` или `protected`).
- Реализация должна быть совместима по сигнатуре и не может сужать доступ: абстрактный `protected` метод реализуется как `protected` или `public`, но не как `private`[^1][^2].
- Абстрактный класс может содержать свойства, константы и обычные методы с реализацией.

_Пример_

```php
<?php

declare(strict_types=1);

abstract class Delivery
{
    abstract public function title(): string;

    abstract public function cost(int $orderTotal): int;
}

final class CourierDelivery extends Delivery
{
    public function title(): string
    {
        return 'Курьер';
    }

    public function cost(int $orderTotal): int
    {
        return $orderTotal >= 1000 ? 0 : 50;
    }
}

final class PickupDelivery extends Delivery
{
    public function title(): string
    {
        return 'Самовывоз';
    }

    public function cost(int $orderTotal): int
    {
        return 0;
    }
}

function deliveryLine(Delivery $delivery, int $orderTotal): string
{
    return $delivery->title() . ': ' . $delivery->cost($orderTotal) . ' лей';
}

echo deliveryLine(new CourierDelivery(), 600) . '<br>';   // Курьер: 50 лей
echo deliveryLine(new PickupDelivery(), 600);             // Самовывоз: 0 лей
```

Абстрактный класс помогает обнаружить три ошибки. Каждая показана отдельно, поскольку после фатальной ошибки выполнение скрипта прекращается.

Попытка создать объект абстрактного класса:

```php
$delivery = new Delivery();
// Fatal error: Uncaught Error: Cannot instantiate abstract class Delivery
```

Наследник, который забыл реализовать абстрактный метод:

```php
final class PostDelivery extends Delivery
{
    public function title(): string
    {
        return 'Почта Молдовы';
    }
}
// Fatal error: Class PostDelivery contains 1 abstract method and must therefore
// be declared abstract or implement the remaining methods (Delivery::cost)
```

Передача объекта, который не является способом доставки:

```php
echo deliveryLine(new Product('Мышь', 299), 600);
// Fatal error: Uncaught TypeError: deliveryLine(): Argument #1 ($delivery)
// must be of type Delivery, Product given, called in ... on line 52
```

Пропущенный `cost()` обнаруживается при объявлении `PostDelivery`, ещё до создания объекта. А если передать неподходящий объект, `TypeError` укажет на вызов `deliveryLine()`, а не на обращение к отсутствующему методу внутри функции.

### Общий код в абстрактном классе

Курьер и почта используют одно правило: при сумме заказа от 1000 лей доставка бесплатна. Чтобы не повторять эту проверку в каждом классе, перенесём её в абстрактного родителя:

```php
abstract class Delivery
{
    public const FREE_FROM = 1000;

    abstract public function title(): string;

    abstract protected function baseCost(): int;

    final public function cost(int $orderTotal): int
    {
        if ($orderTotal >= self::FREE_FROM) {
            return 0;
        }

        return $this->baseCost();
    }
}

final class CourierDelivery extends Delivery
{
    public function title(): string
    {
        return 'Курьер';
    }

    protected function baseCost(): int
    {
        return 50;
    }
}

final class PostDelivery extends Delivery
{
    public function title(): string
    {
        return 'Почта Молдовы';
    }

    protected function baseCost(): int
    {
        return 35;
    }
}

$courier = new CourierDelivery();
$post = new PostDelivery();

echo $courier->cost(600) . '<br>';    // 50
echo $courier->cost(1200) . '<br>';   // 0
echo $post->cost(600);                // 35
```

Схема 7.2 показывает, как выполняется вызов `$courier->cost(600)`.

```text
$courier->cost(600)
    │
    ▼
Delivery::cost()                      код родителя, метод final
    ├── 600 >= 1000? да ──► вернуть 0
    └── нет ──► $this->baseCost()
                    │
                    ▼
            CourierDelivery::baseCost()   код наследника ──► 50
```

_Схема 7.2. Родитель задаёт порядок шагов, наследник реализует один шаг_

Здесь обязанности разделены:

- _Родитель задаёт правило_. Метод `cost()` проверяет сумму заказа, затем вызывает `baseCost()`. Объявление `final` запрещает наследникам менять этот порядок.
- _Наследник задаёт стоимость_. Курьер и почта реализуют `baseCost()` и возвращают свою цену без учёта скидки.
- _Внешний код вызывает только `cost()`_. Защищённый `baseCost()` нельзя вызвать со страницы и обойти проверку порога.

Теперь прежний `PickupDelivery` не сможет наследовать `Delivery`: его метод `cost()` переопределяет финальный метод родителя (`Cannot override final method Delivery::cost()`).

Такую схему, при которой родитель определяет шаги алгоритма, а наследники реализуют отдельные шаги, называют _шаблонным методом (template method)_[^3].

### Ограничение абстрактного класса

Абстрактный класс `Delivery` пригодился для курьера и почты: оба способа используют общее правило бесплатной доставки от 1000 лей. Но что делать, если появится экспресс-доставка за фиксированные 120 лей независимо от суммы заказа?

Её нельзя унаследовать от текущего `Delivery`: метод `cost()` объявлен `final` и всегда возвращает `0` для заказов от 1000 лей. Между тем функция оформления заказа должна работать и с обычной, и с экспресс-доставкой.

Значит, нам нужны две разные вещи:

- _Общий тип_. Он позволит функции принимать любой способ доставки с методами `title()` и `cost()`.
- _Общая реализация_. Она нужна только тем способам, которые действительно используют одно правило расчёта.

Абстрактный класс может дать и тип, и реализацию, но не стоит заставлять все способы доставки наследовать одно правило. Отделить требования к объекту от готового кода позволяют интерфейсы.

## Интерфейсы

### Интерфейс как контракт

Представим, что функция `deliveryLine()` ничего не знает о том, как рассчитывается стоимость доставки. Ей достаточно двух методов:

- Получить название
- Рассчитать цену.

Требования к ним можно записать отдельно от классов.

**Интерфейс (interface)** - описание методов, которые класс обязан предоставить. Интерфейс задаёт их имена, параметры и типы результатов, но не содержит их реализаций[^4].

```php
interface DeliveryMethod
{
    public function title(): string;

    public function cost(int $orderTotal): int;
}
```

Здесь интерфейс `DeliveryMethod` требует два открытых метода. Ключевое слово `implements` означает, что класс обязуется их реализовать. В этом смысле интерфейс называют _контрактом (contract)_.

Рассмотрим два способа доставки, у которых совершенно разные правила расчёта:

```php
final class PickupDelivery implements DeliveryMethod
{
    public function title(): string
    {
        return 'Самовывоз';
    }

    public function cost(int $orderTotal): int
    {
        return 0;
    }
}

final class ExpressDelivery implements DeliveryMethod
{
    public function title(): string
    {
        return 'Экспресс за 2 часа';
    }

    public function cost(int $orderTotal): int
    {
        return 120;
    }
}

function deliveryLine(DeliveryMethod $delivery, int $orderTotal): string
{
    return $delivery->title() . ': ' . $delivery->cost($orderTotal) . ' лей';
}

echo deliveryLine(new PickupDelivery(), 1200) . '<br>';   // Самовывоз: 0 лей
echo deliveryLine(new ExpressDelivery(), 1200);           // Экспресс за 2 часа: 120 лей
```

Оба объекта подходят для параметра `DeliveryMethod`, хотя один возвращает `0`, а другой `120`. Функции не нужно проверять класс объекта: она вызывает методы, которые гарантирует интерфейс.

_Интерфейс определяет, что объект должен уметь, а класс решает, как именно это сделать._

Основные правила синтаксиса:

- Методы интерфейса объявляются без тела и всегда являются `public`.
- Класс указывает интерфейс после `implements` и реализует все обязательные методы.
- Один класс может реализовать несколько интерфейсов через запятую: `class Product implements CartItem, Linkable`.
- Класс может наследовать один родительский класс и одновременно реализовать интерфейсы: `class A extends B implements C, D`.
- Интерфейс может расширять другие интерфейсы через `extends`. Создать объект самого интерфейса через `new` нельзя.

Интерфейсы могут содержать константы. Начиная с PHP 8.4 они также могут объявлять требования к свойствам, но в этой главе нам достаточно методов[^4].

### Проверки интерфейса

Запись `implements` не просто поясняет назначение класса. PHP проверяет соблюдение интерфейса:

1. _При объявлении класса_. Методы должны существовать, быть открытыми и иметь совместимые параметры и типы результатов.
2. _При передаче аргумента_. Функция с параметром `DeliveryMethod` принимает только объекты, реализующие этот интерфейс.
3. _При проверке `instanceof`_. Выражение `$delivery instanceof DeliveryMethod` показывает, реализует ли объект этот интерфейс[^5].

Например, следующий класс не будет объявлен: интерфейс требует, чтобы `cost()` возвращал `int`, а реализация возвращает `float`.

```php
final class DroneDelivery implements DeliveryMethod
{
    public function title(): string
    {
        return 'Доставка дроном';
    }

    public function cost(int $orderTotal): float
    {
        return 80.0;
    }
}
// Fatal error: Declaration of DroneDelivery::cost(...): float
// must be compatible with DeliveryMethod::cost(...): int
```

А вот в следующем классе оба метода существуют и имеют правильные сигнатуры, но он не объявил `implements DeliveryMethod`:

```php
final class BicycleDelivery
{
    public function title(): string { return 'Велокурьер'; }
    public function cost(int $orderTotal): int { return 25; }
}

echo deliveryLine(new BicycleDelivery(), 600);
// TypeError: Argument #1 ($delivery) must be of type DeliveryMethod, BicycleDelivery given
```

PHP проверяет не случайное совпадение методов, а принадлежность объекта к явно объявленному типу. Такой подход называют _номинальной типизацией (nominal typing)_. В отличие от вызова без общего типа, ошибка обнаруживается сразу при передаче неподходящего аргумента.

### Несколько интерфейсов в одном классе

Один объект может выполнять несколько независимых ролей. Например, товар можно добавить в корзину и показать как ссылку в меню. Но подарочная упаковка нужна только в корзине, а категория каталога - только в меню.

Сначала опишем то, что может находиться в корзине. Для каждой позиции корзине нужны название и цена:

```php
interface CartItem
{
    public function title(): string;

    public function price(): int;
}

final class Product implements CartItem
{
    public function __construct(
        public readonly int $id,
        private string $title,
        private int $price,
    ) {
    }

    public function title(): string
    {
        return $this->title;
    }

    public function price(): int
    {
        return $this->price;
    }
}

final class GiftWrap implements CartItem
{
    public function title(): string
    {
        return 'Подарочная упаковка';
    }

    public function price(): int
    {
        return 49;
    }
}

final class Cart
{
    private array $items = [];

    public function add(CartItem $item, int $quantity = 1): void
    {
        $this->items[] = ['item' => $item, 'quantity' => $quantity];
    }

    public function total(): int
    {
        $total = 0;

        foreach ($this->items as $line) {
            $total += $line['item']->price() * $line['quantity'];
        }

        return $total;
    }
}

$cart = new Cart();
$cart->add(new Product(2, 'Мышь Logitech M185', 299), 2);
$cart->add(new GiftWrap());
echo $cart->total(); // 647
```

Теперь опишем другую роль: объект, на страницу которого можно поставить ссылку. Ей подходят и товар, и категория каталога:

```php
interface Linkable
{
    public function title(): string;

    public function url(): string;
}

// Новая версия Product: теперь он реализует два интерфейса.
final class Product implements CartItem, Linkable
{
    public function __construct(
        public readonly int $id,
        private string $title,
        private int $price,
    ) {
    }

    public function title(): string
    {
        return $this->title;
    }

    public function price(): int
    {
        return $this->price;
    }

    public function url(): string
    {
        return '/product.php?id=' . $this->id;
    }
}

final class Category implements Linkable
{
    public function __construct(
        private string $slug,
        private string $title,
    ) {
    }

    public function title(): string
    {
        return $this->title;
    }

    public function url(): string
    {
        return '/catalog.php?category=' . $this->slug;
    }
}

function menuLink(Linkable $page): string
{
    return '<a href="' . htmlspecialchars($page->url()) . '">'
        . htmlspecialchars($page->title()) . '</a>';
}

$mouse = new Product(2, 'Мышь Logitech M185', 299);
echo menuLink($mouse) . '<br>';
echo menuLink(new Category('mice', 'Мыши'));
```

Второй блок показывает _обновлённую версию_ `Product`, а не ещё один класс с тем же именем. Изменилось только объявление `implements CartItem, Linkable` и появился метод `url()`. Теперь функция `menuLink()` принимает и товар, и категорию.

Получились две независимые роли:

- `CartItem` нужен корзине: он обещает методы `title()` и `price()`.
- `Linkable` нужен меню: он обещает методы `title()` и `url()`.

Товар реализует оба интерфейса, упаковка - только `CartItem`, категория - только `Linkable`. Общий метод `title()` товар реализует один раз, потому что его сигнатура одинакова в обоих интерфейсах.

```text
        CartItem                     Linkable
    title(), price()              title(), url()
     ┌─────┴──────┐              ┌──────┴──────┐
 GiftWrap         └── Product ───┘          Category
```

_Схема 7.3. Класс Product выполняет две роли, а подарочная упаковка и категория - по одной_

На схеме 7.3 видно, зачем нужно несколько интерфейсов: один `Product` выполняет две роли, не наследуя два класса. В PHP у класса может быть только один родитель, но интерфейсов он может реализовать несколько.

### Интерфейс и абстрактный класс вместе

Вернёмся к доставке. `DeliveryMethod` уже объединяет самовывоз и экспресс-доставку. Теперь добавим к тому же интерфейсу курьера и почту, сохранив для них общее правило бесплатной доставки от 1000 лей.

Абстрактный класс может _частично реализовать интерфейс_: предоставить общий метод `cost()`, а реализацию `title()` оставить наследникам[^4].

```php
abstract class Delivery implements DeliveryMethod
{
    public const FREE_FROM = 1000;

    abstract public function title(): string;

    abstract protected function baseCost(): int;

    final public function cost(int $orderTotal): int
    {
        if ($orderTotal >= self::FREE_FROM) {
            return 0;
        }

        return $this->baseCost();
    }
}

final class CourierDelivery extends Delivery
{
    public function title(): string
    {
        return 'Курьер';
    }

    protected function baseCost(): int
    {
        return 50;
    }
}

final class PostDelivery extends Delivery
{
    public function title(): string
    {
        return 'Почта Молдовы';
    }

    protected function baseCost(): int
    {
        return 35;
    }
}

echo deliveryLine(new CourierDelivery(), 1200) . '<br>';  // Курьер: 0 лей
echo deliveryLine(new ExpressDelivery(), 1200);           // Экспресс за 2 часа: 120 лей
```

`CourierDelivery` и `PostDelivery` наследуют `Delivery`, поэтому автоматически удовлетворяют требованиям `DeliveryMethod`. `PickupDelivery` и `ExpressDelivery` реализуют тот же интерфейс напрямую. Функция `deliveryLine()` принимает все четыре варианта, хотя общий код расчёта есть только у двух.

```text
DeliveryMethod              интерфейс: title(), cost()
├── Delivery                абстрактный класс: правило бесплатной доставки от 1000 лей
│   ├── CourierDelivery     baseCost() = 50
│   └── PostDelivery        baseCost() = 35
├── PickupDelivery          cost() = 0
└── ExpressDelivery         cost() = 120
```

_Схема 7.4. Способы доставки MiniShop_

_Не путайте интерфейс и абстрактный класс._ Интерфейс задаёт требования, а абстрактный класс может содержать готовый код. Они дополняют друг друга, а не конкурируют.

| Признак                      | Интерфейс                                     | Абстрактный класс                                                  |
| ---------------------------- | --------------------------------------------- | ------------------------------------------------------------------ |
| Что задаёт                   | Обязательные возможности класса               | Общего родителя и, при необходимости, общий код                    |
| Реализация методов           | Нет                                           | Может быть                                                         |
| Методы                       | Только `public`                               | Абстрактные `public` или `protected`, обычные - с любой видимостью |
| Насколько можно использовать | Класс может реализовать несколько интерфейсов | Класс может наследовать только один родительский класс             |
| Когда подходит               | Нужен общий тип для разных реализаций         | Несколько родственных классов используют общее поведение           |

Интерфейс пригодится для заменяемых способов доставки, оплаты или отправки уведомлений. Абстрактный класс стоит добавлять, когда он действительно избавляет от повторения общего кода. Если общей реализации нет, достаточно интерфейса.

## Композиция

### Задача: заказ с доставкой и оплатой

В MiniShop к доставке добавляется оплата: картой без комиссии или наличными при получении с комиссией 20 лей. Если сделать отдельный подкласс `Order` для каждого сочетания, получится следующая схема:

```text
Order
├── CourierCardOrder
├── CourierCashOrder
├── PostCardOrder
├── PostCashOrder
├── PickupCardOrder
├── PickupCashOrder
├── ExpressCardOrder
└── ExpressCashOrder
```

_Схема 7.5. Варианты заказа, описанные наследованием_

Для четырёх способов доставки и двух способов оплаты уже нужно восемь подклассов (схема 7.5). Третий способ оплаты добавит ещё четыре. Между тем доставка и оплата меняются независимо, а при таком наследовании приходится создавать класс для каждого сочетания.

### Понятие композиции

Другой путь состоит в том, чтобы заказ не наследовал способы доставки и оплаты, а хранил их в своих свойствах:

```text
Order
├── $delivery: DeliveryMethod     CourierDelivery, PostDelivery, PickupDelivery, ExpressDelivery
└── $payment: PaymentMethod       CardPayment, CashOnDelivery
```

_Схема 7.6. Заказ, который хранит способ доставки и способ оплаты в свойствах_

На схеме 7.6 класс `Order` один. Он хранит выбранные объекты доставки и оплаты. Для четырёх способов доставки и двух способов оплаты нужны шесть реализаций и один класс заказа. Новый способ оплаты добавит лишь одну реализацию.

**Композиция (composition)** - способ построения класса, при котором объект хранит в своих свойствах другие объекты и поручает им часть своей работы.

_Пример_

Опишем способ оплаты интерфейсом `PaymentMethod` и соберём заказ из корзины, способа доставки и способа оплаты:

```php
interface PaymentMethod
{
    public function title(): string;

    public function fee(int $amount): int;
}

final class CardPayment implements PaymentMethod
{
    public function title(): string
    {
        return 'Картой онлайн';
    }

    public function fee(int $amount): int
    {
        return 0;
    }
}

final class CashOnDelivery implements PaymentMethod
{
    public function title(): string
    {
        return 'Наличными при получении';
    }

    public function fee(int $amount): int
    {
        return 20;
    }
}

final class Order
{
    public function __construct(
        private Cart $cart,
        private DeliveryMethod $delivery,
        private PaymentMethod $payment,
    ) {
    }

    public function total(): int
    {
        $itemsTotal = $this->cart->total();

        return $itemsTotal
            + $this->delivery->cost($itemsTotal)
            + $this->payment->fee($itemsTotal);
    }
}

$cart = new Cart();
$cart->add(new Product(2, 'Мышь Logitech M185', 299), 2);

$order = new Order($cart, new CourierDelivery(), new CashOnDelivery());
echo $order->total() . '<br>';   // 668 = 598 + 50 + 20

$order = new Order($cart, new ExpressDelivery(), new CardPayment());
echo $order->total();            // 718 = 598 + 120 + 0
```

Метод `Order::total()` не зависит от выбранных способов доставки и оплаты. Он вызывает `cost()` и `fee()` через интерфейсы, а переданные объекты сами рассчитывают нужные суммы. При появлении нового способа оплаты `Order` менять не придётся.

Доставку и оплату заказ получает через конструктор. Это _внедрение зависимости (dependency injection)_: необходимые объекты передаются классу извне. Если бы `Order` создавал `new CourierDelivery()` внутри себя, сменить доставку без правки класса было бы сложнее.

### Наследование или композиция

Авторы книги "Design Patterns" рекомендуют предпочитать композицию наследованию[^3]. Это не означает, что наследование плохое: выбор зависит от задачи. В MiniShop встретились четыре варианта:

| Различие                                                    | Средство                        | Пример главы                                 |
| ----------------------------------------------------------- | ------------------------------- | -------------------------------------------- |
| Класс является частным случаем другого и использует его код | Наследование                    | `CourierDelivery extends Delivery`           |
| Часть поведения меняется независимо от остальных частей     | Композиция и интерфейс          | `Order` с `DeliveryMethod` и `PaymentMethod` |
| Объекты отличаются только значением                         | Свойство с данными              | Скидка `discount` из главы 6                 |
| Меняется одно действие, состояние не нужно                  | Функция как значение (callable) | Правило сортировки в `usort()` из главы 5    |

Композиция тоже усложняет код: появляются интерфейсы и отдельные классы, которые нужно соединить. Если вариантов всего два и они не будут меняться, `match` может оказаться проще. Композиция полезна, когда части поведения изменяются независимо.

## Статические свойства и методы

### Члены класса без объекта

В главе 6 цена форматировалась функцией `formatPrice()`, а валюта хранилась в `Product::CURRENCY`. Эти действия связаны, но форматированию не нужен объект товара. Соберём их в одном классе `Price`, метод которого можно вызывать без создания объекта.

**Статический метод (static method)** - метод, объявленный с ключевым словом `static`, который принадлежит классу и вызывается через имя класса без создания объекта[^6].

**Статическое свойство (static property)** - свойство, объявленное с ключевым словом `static`, которое принадлежит классу и имеет одно значение, общее для всего класса[^6].

_Синтаксис_

```php
class ClassName
{
    modifier static type $propertyName = value;

    modifier static function methodName(type $parameter): type
    {
        // $this недоступен
    }
}

ClassName::methodName(arguments)
ClassName::$propertyName
self::methodName(arguments)
self::$propertyName
```

- Обращение выполняется оператором `::`, как к константам класса. Внутри класса используется `self`.
- Перед именем статического свойства после `::` ставится знак `$`, в отличие от константы: `self::$count`, но `self::CURRENCY`.
- В статическом методе нет `$this`, потому что метод вызывается не для объекта. Попытка обратиться к `$this` завершается ошибкой `Using $this when not in object context`.
- Обычный метод нельзя вызвать через `::` как статический: такой вызов завершается ошибкой `Non-static method ... cannot be called statically`[^6].

_Пример_

```php
<?php

declare(strict_types=1);

final class Price
{
    public const CURRENCY = 'лей';

    public static function format(int $amount): string
    {
        return number_format($amount, 0, ',', ' ') . ' ' . self::CURRENCY;
    }
}

echo Price::format(14999);   // 14 999 лей
```

Функция `number_format()` осталась прежней, а форматирование и валюта теперь собраны в одном классе.

### Статическое свойство

Статическое свойство общее для всех объектов класса. Допустим, каждый новый заказ получает номер. Для примера возьмём упрощённый `Order`, содержащий только счётчик и номер заказа:

```php
<?php

declare(strict_types=1);

final class Order
{
    private static int $lastNumber = 0;

    public readonly int $number;

    public function __construct()
    {
        self::$lastNumber++;
        $this->number = self::$lastNumber;
    }

    public static function count(): int
    {
        return self::$lastNumber;
    }
}

$first = new Order();
$second = new Order();

echo $first->number . '<br>';    // 1
echo $second->number . '<br>';   // 2
echo Order::count();             // 2
```

У каждого объекта свой `$number`, но оба конструктора изменяют одно статическое свойство `$lastNumber`. Поэтому заказы получили номера 1 и 2.

> [!IMPORTANT]
> В обычном PHP-приложении каждый HTTP-запрос выполняет скрипт заново. Поэтому при следующей загрузке страницы `$lastNumber` снова начнётся с `0`: разные покупатели могут получить заказ с номером `1`. Статические свойства не подходят для постоянных номеров заказов. Такие данные нужно хранить в базе.

Не путайте статическое свойство со статической переменной функции. В обычном PHP-запросе оба сохраняют значение между вызовами, но переменная видна только внутри функции, а свойство доступно из методов класса (и извне, если оно `public`).

## Магические константы и методы

PHP умеет сам подставлять сведения о месте в программе и вызывать специальные методы при действиях с объектами. Эти возможности называют магическими константами и методами. У них похожие имена с двумя символами подчёркивания, но разные задачи.

### Магические константы

В сообщении об ошибке полезно указать имя метода. Но если вписать его вручную, после переименования строка устареет. PHP может подставить имя автоматически.

**Магическая константа (magic constant)** - встроенная константа PHP, значение которой определяется местом в коде, где она записана[^8].

Например, `__LINE__` возвращает номер строки, на которой находится запись. Значение константы нельзя изменить присваиванием. Её имя не зависит от регистра[^8].

| Константа      | Значение                                                                      |
| -------------- | ----------------------------------------------------------------------------- |
| `__LINE__`     | Номер текущей строки файла                                                    |
| `__FILE__`     | Полный путь к текущему файлу                                                  |
| `__DIR__`      | Каталог текущего файла без завершающей косой черты (кроме корневого каталога) |
| `__FUNCTION__` | Имя текущей функции или метода                                                |
| `__CLASS__`    | Имя текущего класса                                                           |
| `__METHOD__`   | Имя класса и метода в виде `ClassName::methodName`                            |

К магическим константам близка запись `ClassName::class`, которая возвращает строку с именем класса. PHP при этом не проверяет, существует ли такой класс. Начиная с PHP 8.0 запись применима и к объекту: `$object::class` возвращает имя его класса[^9].

_Пример_

```php
<?php

declare(strict_types=1);

final class Cart
{
    private array $items = [];

    public function add(string $title, int $quantity): void
    {
        if ($quantity <= 0) {
            throw new InvalidArgumentException(
                __METHOD__ . ': количество должно быть положительным, получено ' . $quantity
            );
        }

        $this->items[] = ['title' => $title, 'quantity' => $quantity];
    }

    public function describe(): string
    {
        return __CLASS__ . ', метод ' . __FUNCTION__ . ', строка ' . __LINE__;
    }
}

$cart = new Cart();

echo $cart->describe() . '<br>';   // Cart, метод describe, строка 22 (если считать от <?php)
echo $cart::class . '<br>';        // Cart

try {
    $cart->add('Мышь', 0);
} catch (InvalidArgumentException $e) {
    echo $e->getMessage();   // Cart::add: количество должно быть положительным, получено 0
}
```

На практике `__METHOD__` помогает указать метод в сообщении об ошибке, а `__DIR__` - построить путь к файлу рядом со скриптом: `__DIR__ . '/data/products.json'`. В отличие от `Price::CURRENCY`, магические константы определены PHP, а их значения зависят от места в коде.

### Магические методы

Один магический метод уже встречался в главе 6: конструктор `__construct()`, который PHP вызывает сам при выполнении `new`.

**Магический метод (magic method)** - метод со специальным именем, начинающимся с двух символов подчёркивания, который PHP вызывает автоматически при определённом действии с объектом[^10].

Имена, начинающиеся с `__`, зарезервированы для специальных методов PHP. Все магические методы, кроме `__construct()`, `__destruct()` и `__clone()`, должны быть `public`[^10]. В таблице показаны методы из этой главы.

| Действие с объектом                                        | Вызываемый метод                               |
| ---------------------------------------------------------- | ---------------------------------------------- |
| Использование объекта как строки                           | `__toString()`                                 |
| Чтение, запись, `isset()`, `unset()` недоступного свойства | `__get()`, `__set()`, `__isset()`, `__unset()` |
| Вызов недоступного метода                                  | `__call()`, `__callStatic()`                   |
| Вызов объекта как функции                                  | `__invoke()`                                   |
| Копирование оператором `clone`                             | `__clone()`                                    |
| Уничтожение объекта                                        | `__destruct()`                                 |
| Вывод `var_dump()`                                         | `__debugInfo()`                                |

#### Преобразование объекта в строку

Если у объекта нет строкового представления, `echo $product` приведёт к ошибке `Object of class Product could not be converted to string`. Метод `__toString()` определяет, какую строку возвращать. PHP использует её в `echo`, при объединении строк и при преобразовании `(string) $object`.

_Синтаксис_

```php
public function __toString(): string
```

- Метод не принимает параметров и должен вернуть строку.
- Начиная с PHP 8.0 класс с методом `__toString()` автоматически реализует встроенный интерфейс `Stringable`, поэтому параметр типа `Stringable` примет любой такой объект[^11].
- В режиме `strict_types=1` объект нельзя передать в параметр типа `string`: вызов завершится ошибкой `TypeError` даже при наличии `__toString()`.

_Пример_

```php
<?php

declare(strict_types=1);

final class Product
{
    public function __construct(
        private string $title,
        private int $price,
    ) {
    }

    public function __toString(): string
    {
        return $this->title . ' (' . $this->price . ' лей)';
    }
}

$mouse = new Product('Мышь Logitech M185', 299);

echo $mouse . '<br>';                    // Мышь Logitech M185 (299 лей)
echo "В корзине: $mouse<br>";            // В корзине: Мышь Logitech M185 (299 лей)
var_dump($mouse instanceof Stringable);  // bool(true)
```

`__toString()` задаёт одно представление. Если товар нужно по-разному выводить в каталоге и письме, лучше сделать отдельные методы форматирования.

#### Обращение к недоступным свойствам

Начиная с PHP 8.2 создание необъявленных свойств устарело. Если набор доступных свойств заранее неизвестен, можно управлять обращениями к ним через четыре магических метода[^12].

_Синтаксис_

```php
public function __get(string $name): mixed
public function __set(string $name, mixed $value): void
public function __isset(string $name): bool
public function __unset(string $name): void
```

- `__get()` вызывается при чтении недоступного свойства, то есть несуществующего или закрытого для вызывающего кода. Параметр `$name` содержит имя свойства, результат метода становится значением выражения.
- `__set()` вызывается при записи в недоступное свойство.
- `__isset()` вызывается, когда к недоступному свойству применяют `isset()` или оператор `??`.
- `__unset()` вызывается, когда к недоступному свойству применяют `unset()`.

_Пример_

Предположим, набор настроек магазина приходит из файла и заранее неизвестен. Класс `Config` хранит их в массиве, но позволяет читать как свойства: `$config->currency`. Изменять настройки через объект нельзя.

```php
<?php

declare(strict_types=1);

final class Config
{
    public function __construct(
        private array $values,
    ) {
    }

    public function __get(string $name): mixed
    {
        if (!array_key_exists($name, $this->values)) {
            throw new InvalidArgumentException('Неизвестная настройка: ' . $name);
        }

        return $this->values[$name];
    }

    public function __set(string $name, mixed $value): void
    {
        throw new LogicException('Настройки доступны только для чтения');
    }

    public function __isset(string $name): bool
    {
        return isset($this->values[$name]);
    }
}

$config = new Config([
    'shopName' => 'MiniShop',
    'currency' => 'лей',
]);

echo $config->shopName . '<br>';                          // MiniShop
var_dump(isset($config->currency));                       // bool(true)
echo '<br>' . ($config->phone ?? 'не указан') . '<br>';   // не указан

try {
    $config->currency = 'EUR';
} catch (LogicException $e) {
    echo $e->getMessage() . '<br>';   // Настройки доступны только для чтения
}

try {
    echo $config->curency;
} catch (InvalidArgumentException $e) {
    echo $e->getMessage();   // Неизвестная настройка: curency
}
```

`__get()` позволяет читать настройки и выдаёт понятную ошибку при опечатке `curency`. `__set()` запрещает запись. А `isset()` и `??` сначала обращаются к `__isset()`, а не к `__get()`. Без `__isset()` проверка `isset($config->currency)` вернула бы `false`, даже если настройка есть в массиве. Поэтому при динамическом чтении свойств эти методы часто используют вместе.

#### Вызов недоступных методов

Метод `__call()` вызывается при обращении к недоступному методу объекта, а `__callStatic()` - при таком же статическом вызове через `::`[^12].

_Синтаксис_

```php
public function __call(string $name, array $arguments): mixed
public static function __callStatic(string $name, array $arguments): mixed
```

- `$name` - имя вызванного метода.
- `$arguments` - массив переданных аргументов.

_Пример_

Допустим, нужно записывать вызовы методов доставки, не изменяя сам класс доставки. Создадим _заместителя (proxy)_: он примет вызов, запишет его и передаст исходному объекту.

```php
final class LoggingProxy
{
    public function __construct(
        private object $target,
    ) {
    }

    public function __call(string $name, array $arguments): mixed
    {
        echo 'Вызов ' . $name . '(' . implode(', ', $arguments) . ')<br>';

        return $this->target->$name(...$arguments);
    }
}

$delivery = new LoggingProxy(new CourierDelivery());

echo $delivery->cost(600);
// Вызов cost(600)
// 50
```

Тип `object` принимает объект любого класса. В `LoggingProxy` нет `cost()`, поэтому PHP вызывает `__call('cost', [600])`. Заместитель берёт имя метода из `$name` и через `...` передаёт аргументы исходному объекту.

`LoggingProxy` не объявляет `implements DeliveryMethod`, поэтому функция `deliveryLine()` его не примет. В обычном приложении методы лучше объявлять явно; `__call()` полезен, когда их набор заранее неизвестен.

#### Объект как функция

Метод `__invoke()` позволяет вызвать объект как функцию: `$object(arguments)`. Такой объект подходит для параметра типа `callable` и может использоваться в функциях вроде `array_filter()`[^13].

_Пример_

Правило отбора товаров по диапазону цен оформлено объектом и передано в `array_filter()`:

```php
<?php

declare(strict_types=1);

final class Product
{
    public function __construct(
        public readonly string $title,
        public readonly int $price,
    ) {
    }
}

final class PriceRange
{
    public function __construct(
        private int $min,
        private int $max,
    ) {
    }

    public function __invoke(Product $product): bool
    {
        return $product->price >= $this->min && $product->price <= $this->max;
    }
}

$catalog = [
    new Product('Ноутбук Lenovo IdeaPad 3', 14999),
    new Product('Мышь Logitech M185', 299),
    new Product('Кабель HDMI', 149),
];

$cheap = new PriceRange(100, 500);

foreach (array_filter($catalog, $cheap) as $product) {
    echo $product->title . '<br>';
}
// Мышь Logitech M185
// Кабель HDMI
```

Здесь подошла бы и стрелочная функция. Объект удобнее, если правило имеет настройки, например границы цен, и используется повторно.

#### Копирование объекта

Оператор `clone` создаёт поверхностную копию объекта. Обычные значения свойств копируются, но вложенные объекты остаются общими. После копирования PHP вызывает у новой копии `__clone()`, в котором можно отдельно скопировать вложенные объекты[^14].

_Пример_

Покупатель повторяет прошлый заказ, но с доставкой по другому адресу. Класс `Order` здесь упрощён: в нём есть только адрес и сумма.

```php
<?php

declare(strict_types=1);

final class Address
{
    public function __construct(
        public string $city,
        public string $street,
    ) {
    }
}

final class Order
{
    public function __construct(
        public Address $address,
        public int $total,
    ) {
    }

    public function __clone(): void
    {
        $this->address = clone $this->address;
    }
}

$order = new Order(new Address('Кишинёв', 'ул. Пушкина, 1'), 668);

$repeat = clone $order;
$repeat->address->city = 'Бельцы';

echo $order->address->city . '<br>';   // Кишинёв
echo $repeat->address->city;           // Бельцы
```

В `__clone()` переменная `$this` указывает на копию заказа. Мы создаём для неё отдельный `Address`, поэтому изменение адреса второго заказа не затронет первый. Без этого оба заказа ссылались бы на один адрес (схема 7.7).

```text
Без __clone()                              С __clone()

$order ──► Order                           $order ──► Order
             address ──┐                                address ──► Address (Кишинёв)
                       ├──► Address (Бельцы)
$repeat ─► Order       │                   $repeat ─► Order
             address ──┘                                address ──► Address (Бельцы)
```

_Схема 7.7. Адрес в копии заказа без метода \_\_clone() и с ним_

#### Уничтожение объекта

**Деструктор (destructor)** - магический метод `__destruct()`, который PHP вызывает, когда объект больше не доступен ни через одну переменную или свойство либо когда скрипт завершает работу[^15].

_Пример_

```php
<?php

declare(strict_types=1);

final class Report
{
    public function __construct(
        private string $title,
    ) {
        echo 'Создан отчёт "' . $this->title . '"<br>';
    }

    public function __destruct()
    {
        echo 'Уничтожен отчёт "' . $this->title . '"<br>';
    }
}

function buildDailyReport(): void
{
    $report = new Report('продажи за день');
    echo 'Формирование отчёта<br>';
}

buildDailyReport();
echo 'Последняя строка скрипта<br>';
// Создан отчёт "продажи за день"
// Формирование отчёта
// Уничтожен отчёт "продажи за день"
// Последняя строка скрипта
```

После выхода из функции переменная `$report` исчезает, и PHP уничтожает объект. В обычном PHP-запросе оставшиеся объекты уничтожаются при завершении скрипта. Поэтому, в отличие от C++, деструктор для освобождения ресурсов чаще всего писать не нужно.

#### Отладочный вывод

`var_dump()` показывает в том числе закрытые свойства. Если в объекте хранится секретный ключ, он может попасть в отладочный вывод. Метод `__debugInfo()` позволяет указать, какие данные показывать вместо свойств объекта[^10].

```php
final class PaymentGateway
{
    public function __construct(
        private string $merchantId,
        private string $secretKey,
    ) {
    }

    public function __debugInfo(): array
    {
        return [
            'merchantId' => $this->merchantId,
            'secretKey' => '***',
        ];
    }
}

var_dump(new PaymentGateway('minishop-01', 'sk_live_51HbX9'));
// object(PaymentGateway)#1 (2) {
//   ["merchantId"]=>
//   string(11) "minishop-01"
//   ["secretKey"]=>
//   string(3) "***"
// }
```

Значение `$secretKey` внутри объекта при этом не изменилось.

#### Ограничения магических методов

Динамический доступ через `__get()` и `__call()` удобен, но у него есть недостатки:

- _Опечатки обнаруживаются поздно_. Неизвестное имя попадает в `__get()` или `__call()`, и ошибка может остаться незамеченной, если эти методы его не проверяют.
- _Подсказки редактора ограничены_. Динамические свойства и методы не всегда видны инструментам анализа.
- _Проверка типов сложнее_. `__get()` обычно возвращает `mixed`, а `__call()` получает аргументы массивом.

Поэтому для обычного кода предпочтительнее явно объявленные свойства и методы. `__get()`, `__set()` и `__call()` стоит применять там, где динамический доступ действительно нужен. Это ограничение не относится ко всем магическим методам, например `__construct()` и `__clone()`.

## Собираем вместе

Теперь соберём страницу оформления заказа MiniShop из знакомых частей: корзины, доставки, оплаты и форматирования цены. Полная программа находится в [27_checkout.php](code/27_checkout.php). На странице используются немного расширенные версии двух классов:

- `Cart` хранит позиции в `$lines` и возвращает их методом `lines()`. При неверном количестве в сообщении об ошибке используется `__METHOD__`.
- `Order` открывает для чтения корзину, доставку и оплату через свойства `public readonly`.

```php
final class Order
{
    public function __construct(
        public readonly Cart $cart,
        public readonly DeliveryMethod $delivery,
        public readonly PaymentMethod $payment,
    ) {
    }

    public function deliveryCost(): int
    {
        return $this->delivery->cost($this->cart->total());
    }

    public function paymentFee(): int
    {
        return $this->payment->fee($this->cart->total());
    }

    public function total(): int
    {
        return $this->cart->total() + $this->deliveryCost() + $this->paymentFee();
    }
}

// В настоящем магазине код доставки придёт из формы.
$deliveryCode = 'courier';
$delivery = match ($deliveryCode) {
    'courier' => new CourierDelivery(),
    'post' => new PostDelivery(),
    'pickup' => new PickupDelivery(),
    'express' => new ExpressDelivery(),
    default => throw new InvalidArgumentException('Неизвестная доставка'),
};

$cart = new Cart();
$cart->add(new Product(2, 'Мышь Logitech M185', 299), 2);
$cart->add(new Product(5, 'Коврик для мыши', 89));
$cart->add(new GiftWrap());

$order = new Order($cart, $delivery, new CashOnDelivery());

?>
<!DOCTYPE html>
<html lang="ru">
<head>
    <meta charset="UTF-8">
    <title>MiniShop - оформление заказа</title>
</head>
<body>
    <h1>Оформление заказа</h1>

    <table>
        <?php foreach ($order->cart->lines() as $line): ?>
            <tr>
                <td><?= htmlspecialchars($line['item']->title()) ?></td>
                <td><?= $line['quantity'] ?> × <?= Price::format($line['item']->price()) ?></td>
            </tr>
        <?php endforeach; ?>
    </table>

    <p>Товары: <?= Price::format($order->cart->total()) ?></p>
    <p>Доставка (<?= htmlspecialchars($order->delivery->title()) ?>): <?= Price::format($order->deliveryCost()) ?></p>
    <p>Оплата (<?= htmlspecialchars($order->payment->title()) ?>): <?= Price::format($order->paymentFee()) ?></p>
    <p><strong>Итого: <?= Price::format($order->total()) ?></strong></p>
</body>
</html>
```

В этом примере `match` преобразует код доставки из формы в объект. Ветвь `default` сообщает об ошибке, если код неизвестен. Начиная с PHP 8.0 `throw` можно записывать как выражение, в том числе в `match`[^7].

Обратите внимание на три решения:

- _Состав заказа легко изменять_. Упаковка добавляется как обычная позиция корзины, а для оплаты картой достаточно передать `new CardPayment()`.

## Типичные ошибки

### Класс без записи implements

```php
final class Coupon
{
    public function title(): string { return 'Купон'; }
    public function price(): int { return -100; }
}

$cart->add(new Coupon());   // TypeError: must be of type CartItem, Coupon given
```

Наличие подходящих методов не заменяет объявление `implements CartItem`.

### Метод интерфейса объявлен не открытым

```php
interface CartItem
{
    protected function price(): int;
}
// Fatal error: Access type for interface method CartItem::price() must be public
```

Реализация методов интерфейса должна быть `public`.

### Создание объекта интерфейса или абстрактного класса

```php
$item = new CartItem();       // Error: Cannot instantiate interface CartItem
$delivery = new Delivery();   // Error: Cannot instantiate abstract class Delivery
```

Создать можно объект конкретного класса, но не самого интерфейса или абстрактного класса.

### Обращение к $this в статическом методе

```php
public static function format(int $amount): string
{
    return number_format($amount) . ' ' . $this->currency;
    // Error: Using $this when not in object context
}
```

В статическом методе нет `$this`. Для данных класса используйте константы и статические свойства через `self::`.

### Номер заказа в статическом свойстве

```php
final class Order
{
    private static int $lastNumber = 0;   // при каждом запросе снова 0
}
```

В обычном PHP-приложении статическое свойство не сохраняет значение между HTTP-запросами. Постоянные номера заказов хранят в базе данных.

### Метод `__get()` без `__isset()`

```php
var_dump(isset($config->currency));   // bool(false), если __isset() не объявлен
```

`isset()` вызывает `__isset()`, поэтому одного `__get()` недостаточно.

| Элемент                                        | Синтаксис                                                                    | Назначение                                      |
| ---------------------------------------------- | ---------------------------------------------------------------------------- | ----------------------------------------------- |
| Абстрактный класс                              | `abstract class ClassName`                                                   | Общий родитель, объект которого создать нельзя  |
| Абстрактный метод                              | `abstract public function methodName(): type;`                               | Метод, который обязан реализовать наследник     |
| Интерфейс                                      | `interface InterfaceName { ... }`                                            | Набор открытых методов без реализации           |
| Реализация интерфейса                          | `class ClassName implements A, B`                                            | Обязательство класса иметь методы интерфейсов   |
| Расширение интерфейса                          | `interface A extends B, C`                                                   | Интерфейс, включающий методы других интерфейсов |
| Статический метод                              | `public static function methodName()`, `ClassName::methodName()`             | Метод класса без объекта                        |
| Статическое свойство                           | `private static int $name`, `self::$name`                                    | Значение, общее для класса в пределах запроса   |
| Магические константы                           | `__LINE__`, `__FILE__`, `__DIR__`, `__FUNCTION__`, `__CLASS__`, `__METHOD__` | Сведения о месте в коде                         |
| Имя класса                                     | `ClassName::class`, `$object::class`                                         | Строка с полным именем класса                   |
| `__toString()`                                 | `public function __toString(): string`                                       | Объект в роли строки                            |
| `__get()`, `__set()`, `__isset()`, `__unset()` | `public function __get(string $name): mixed`                                 | Обращение к недоступным свойствам               |
| `__call()`, `__callStatic()`                   | `public function __call(string $name, array $arguments): mixed`              | Вызов недоступного метода                       |
| `__invoke()`                                   | `public function __invoke(...)`                                              | Объект в роли функции                           |
| `__clone()`                                    | `public function __clone(): void`                                            | Действия с копией после `clone`                 |
| `__destruct()`                                 | `public function __destruct()`                                               | Действия при уничтожении объекта                |
| `__debugInfo()`                                | `public function __debugInfo(): array`                                       | Данные для `var_dump()`                         |

## Резюме

1. Полиморфизм позволяет вызывать один метод у объектов разных классов, получая поведение каждого из них.
2. Абстрактный класс нельзя создать через `new`. Наследники реализуют его абстрактные методы и могут использовать общий код.
3. Интерфейс задаёт требования к классу. Класс может реализовать несколько интерфейсов через `implements`.
4. Интерфейс обеспечивает общий тип без общей реализации. Абстрактный класс нужен, когда нескольким наследникам полезен один и тот же код.
5. Композиция позволяет сочетать независимые части поведения без отдельного подкласса для каждого сочетания.
6. Статические методы вызываются без объекта, а статические свойства в обычном PHP-запросе не сохраняются между загрузками страниц.
7. Магические константы подставляют сведения о месте в коде; `ClassName::class` возвращает имя класса.
8. Магические методы PHP вызывает автоматически. Динамический доступ через `__get()` и `__call()` следует использовать осторожно.
